# 業務管理システム

チームの業務を一元管理するための汎用Webアプリ（業務管理フレームワーク）です。
**タスク / 定型・定期業務 / スキル・業務（スキルテストを含む） / 年休** をここで管理し、メールやチャットでの連絡を最小化することを目指します。

- **技術**: Python 3.9 + Flask + SQLite3（Flask-SQLAlchemy / Flask-Login / Jinja2 / Bootstrap 5）
- **想定環境**: サーバーで常駐起動し、メンバーの PC からブラウザでアクセス
- **規模**: 小規模チーム向け（SQLite で十分な規模を想定）

---

## 主な機能

| 機能 | 概要 |
|------|------|
| **タスク管理** | 登録（マネージャーのみ）／一覧・絞り込み／詳細／編集／ステータス更新／削除。複数担当・開始日/期限・**規模（負荷の目安）**・**進捗状況**の記載・**成果（定量/定性）** に対応。完了にするには成果（実績）の入力が必要。メンバーは計画系項目（優先度/日付/規模/担当者）を変更不可。 |
| **定型・定期業務** | 各自の繰り返し業務を管理（担当者/業務名/目的/回数/頻度/1回所要/内容/手順書状況）。全員が登録・編集可。ヒト別の件数・月間工数・手順書進捗のサマリー表つき。 |
| **スキル・業務** | スキルマップ（テクニカル/コンセプチュアル/ヒューマンの3区分）。横軸に **ヒト（到達度）** と **業務（必要スキル・レベル）** を任意に表示。別ビューで **業務×ヒトの対応可否表**、メンバー個別画面に **育成計画（業務対応に必要なスキルの過不足）**。マネージャーのみ。 |
| **スキルテスト** | メンバーが **有効なテクニカルスキル** ごとに、AI が作った4択問題（既定 30問・約58分）を受験。結果のレベル（Lv1〜4）が今の到達度より高ければ **到達度に自動で登録**（下がることはない）。1問ずつ・制限時間はサーバーで計測・正解はブラウザに送らない・画面から離れた回数を記録。マネージャーは受験履歴（全問の内容・回答・所要時間・離脱回数）・問題プール（AIで補充・問題の無効化）・設定を管理。詳しくは「[スキルテスト](#スキルテスト)」。 |
| **年休** | 承認なしの見える化。単日登録（全休/半休）、月カレンダー（土日色分け・同日上限の調整依頼）、取消は本人のみ。 |
| **チーム管理** | チームマスタの追加/名称変更/有効無効、人×チームの紐づけ（兼務対応）、**メンバー（ユーザー）の追加・削除**。マネージャーのみ。 |
| **マネージャーダッシュボード** | チーム俯瞰（タスク進捗/直近1か月の休暇予定/スキル保有状況）、**ヒト別 負荷・案件状況**（タスク＋定型業務の月間工数を合算・余力表示）、メンバーの活動状況、**全タスクのガントチャート**（期間・担当者フィルタ・ステータス色分け・カミナリ線）。 |
| **週報（自動作成・メール送信）** | タスク情報から「チーム全体＋1人1ページ」の週報を Word で作成し、毎週決まった曜日・時刻にメールで自動送信。画面から今すぐ作成（ダウンロード/テスト送信/本番送信）も可能。AI（ChatGPT互換API）で文章を整形（未設定ならルールベース）。マネージャーのみ（ナビの「定期メール」）。詳しくは「[週報](#週報自動作成メール送信)」。 |
| **期限超過通知（毎朝のメール）** | 営業日（土日・祝日以外）の毎朝、期限を過ぎた未完了タスクの一覧を1通のメールで自動送信。状態（未着手／進行中・保留）ごと・担当者ごとにまとめ、直近の進捗記載とタスクへのリンクを付ける。画面でプレビュー・テスト送信・今すぐ送信も可能。マネージャーのみ（ナビの「定期メール」）。詳しくは「[期限超過通知](#期限超過通知毎朝のメール)」。 |
| **Excel データ出力** | 各メニューの全データ（現在＋履歴。スキルテストの受験履歴・全回答・問題を含む）を `.xlsx` で出力。マネージャーのみ。 |

### 役割（ロール）

**マネージャー（`manager`） / メンバー（`member`）** の2種類。マネージャーが全機能（スキル・スキルテスト管理・各ダッシュボード・チーム管理・データ出力・定期メール〔週報・期限超過通知〕を含む）を利用でき、メンバーは一般利用（タスク/定型業務/年休）とスキルテストの受験が中心です。マネージャーはスキル管理の対象外のため、スキルテストは受験しません。

## セットアップ

```bash
# 1.（推奨）仮想環境
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/Mac

# 2. 依存パッケージ
pip install -r requirements.txt

# 3. 初期データ（ダミーユーザー・サンプルデータ）の投入
python seed.py
```

初回の起動（`seed.py` を含む）で、設定ファイル `instance/config.py` が自動作成されます。
秘密鍵と管理者パスワードはこのとき自動生成されます。接続先などの設定は「[設定ファイル](#設定ファイルinstanceconfigpy)」を参照してください。

## 起動

### 本番（サーバーで他 PC に公開）
```bash
python serve.py
```
- `waitress`（本番向けの WSGI サーバー）で起動します。待ち受けのアドレス・ポートは `instance/config.py` の `SERVER_HOST` / `SERVER_PORT`（既定 `0.0.0.0` / `8050`）。
- メンバーは `http://（サーバーのIPアドレス）:8050` でアクセスします。
- **定期メール（週報・期限超過通知）の自動送信は `serve.py` で起動したときだけ** 動きます（以前の `waitress-serve --call app:create_app` の代わりにこちらを使ってください）。

### 開発・動作確認（自分の PC）
```bash
python run.py
```
ブラウザで <http://127.0.0.1:8050> を開く（Flask の開発サーバー。本番には使わない）。
`run.py` では **定期メール（週報・期限超過通知）の自動送信は行われません**（画面からの手動送信・テスト送信は使えます）。`seed.py` / `migrate.py` でも自動送信は行われません。

## ログインと認証

ログインは **①LDAP（本人確認）→ ②アプリ登録チェック** の2段階です。

1. **本人確認**: `app/auth/ldap_client.py` の `authenticate()`（現状はダミー実装）。本番はこの関数内の「LDAP-API」ブロックを実 API に差し替えるだけで移行できます。
2. **アプリ登録チェック**: LDAP で本人確認できても、**アプリに登録済み・有効なユーザーでなければログインを拒否**します。新しいメンバーはマネージャーが「チーム管理 → メンバーの管理」で登録してからログイン可能になります。

### 固定ローカル管理者
LDAPとは独立に常に有効な管理者アカウントを1つ用意しています（初期設定・緊急用。本番でLDAPに差し替えても残ります）。

- ID: `admin` / パスワード: `instance/config.py` の `ADMIN_PASSWORD`
- パスワードは初回起動時に導入先ごとのランダムな値が自動で入ります。`instance/config.py` を開いて確認し、必要に応じて変更してください（変更後はサーバーを再起動）。
- `ADMIN_PASSWORD` を空にすると、`admin` でのログインは無効になります。

### 動作確認用ダミーアカウント（開発用。本番LDAP導入で不要）
`kacho`（マネージャー）/ `leader`・`yamada`・`suzuki`・`tanaka`（メンバー）。パスワードはすべて `password`。

## 設定ファイル（instance/config.py）

環境によって変わる値（秘密鍵・管理者パスワード・LDAP / AI / メールの接続先など）は、すべて **`instance/config.py` の1ファイル** にまとめて記入します。

- `instance/config.py` は DB（`instance/app.db`）と同じフォルダにあり、**Git 管理外** です。パスワードやキーがリポジトリに入ることはありません。
- ファイルが無い状態で起動すると、リポジトリ直下の見本 **`config.example.py`** をもとに **自動作成** されます（既にあるファイルが上書きされることはありません）。作成時は場所だけが画面（コンソール）に表示されます。
  - `SECRET_KEY` と `ADMIN_PASSWORD` にはランダムな値が自動で入ります。
  - 以前の「AI接続設定」画面で保存した接続先・APIキー・モデルが DB に残っている場合は、作成時に **1回だけ** `AI_API_URL` / `AI_API_KEY` / `AI_MODEL` に引き継ぎます（DB は読み取り専用で開き、変更しません）。
- 書式は Python です（文字列は `"..."`、アドレスの一覧は `[...]`）。値を変更したら **サーバーを再起動** すると反映されます。
- ファイルに書かれていない項目は `app/config.py` の既定値が使われます。後から追加された項目（例: `APP_BASE_URL` / `OVERDUE_MAIL_TO`）は、既にある `instance/config.py` には自動では追記されないため、使う場合は `config.example.py` を参考に書き足してください。
- **環境変数は使いません**（設定はこのファイルだけで完結します）。以前のバージョンで使っていた `.env` ファイルは読み込まれないため、残っている場合は削除してください。

| 項目 | 用途 | 既定値 |
|------|------|------|
| `SECRET_KEY` | セッション暗号化キー（自動作成時にランダム生成）。空なら起動ごとに一時的な鍵を使用（再起動でログアウト） | 空 |
| `ADMIN_PASSWORD` | 固定ローカル管理者 `admin` のパスワード（自動作成時にランダム生成）。空なら `admin` は無効 | 空 |
| `LDAP_API_URL` | LDAP認証APIのURL（本番で使用） | 空 |
| `AI_API_URL` | ChatGPT（OpenAI互換）APIのエンドポイント。空なら OpenAI 公式 | 空 |
| `AI_API_KEY` | APIキー。`AI_API_URL` とどちらも空ならAIは使わない（週報はルールベースで作成、スキルテストは問題プールにある問題だけで出題） | 空 |
| `AI_MODEL` | 使用するモデル名 | `gpt-4o-mini` |
| `AI_TIMEOUT` | AIの応答待ちタイムアウト（秒） | `60` |
| `MAIL_SMTP_SERVER` | メール送信サーバー（ホスト名またはIPアドレス）。空ならメール送信不可 | 空 |
| `MAIL_SMTP_PORT` | 送信サーバーのポート番号 | `25` |
| `MAIL_USE_TLS` | `True` なら STARTTLS で暗号化（サーバー証明書とホスト名を検証） | `False` |
| `MAIL_USERNAME` / `MAIL_PASSWORD` | 送信サーバーの認証情報（空なら認証しない） | 空 |
| `MAIL_FROM` | 差出人アドレス | 空 |
| `MAIL_TO` / `MAIL_CC` | 宛先（To）・同報（Cc）のアドレス一覧 | `[]` |
| `MAIL_TEST_TO` | テスト送信の宛先一覧（空なら `MAIL_FROM` 宛て） | `[]` |
| `OVERDUE_MAIL_TO` / `OVERDUE_MAIL_CC` | 期限超過通知の宛先（To）・同報（Cc）の一覧。`OVERDUE_MAIL_TO` が空なら `MAIL_TO` / `MAIL_CC` に送る（そのとき `OVERDUE_MAIL_CC` は使わない） | `[]` |
| `APP_BASE_URL` | メールに載せるタスクへのリンクの基準URL（メンバーの PC からこのアプリを開くときの URL。末尾の `/` は不要）。空ならリンクなし（タスク名だけ） | 空 |
| `SERVER_HOST` / `SERVER_PORT` | `python serve.py` で起動したときの待ち受けアドレス・ポート（`run.py` はポートのみ使用） | `0.0.0.0` / `8050` |

記入例（値はすべて例です）:
```python
AI_API_KEY = "sk-..."                      # OpenAI公式を使う場合
MAIL_SMTP_SERVER = "smtp.example.com"
MAIL_FROM = "noreply@example.com"
MAIL_TO = ["manager@example.com"]
APP_BASE_URL = "http://192.0.2.10:8050"    # メールのリンク用（サーバーのアドレス）
```

## 週報（自動作成・メール送信）

マネージャーがナビの「**定期メール**」→「**週報**」から設定します（メンバーには表示されません）。

### 作成される週報
- 1回の作成で **Word ファイル1つ**。構成は「タイトル・対象期間」→「**チーム全体**」のまとめ（文章＋メンバー別の集計表）→ 改ページして **1人1ページ** の個人分。
- 材料は **タスク情報だけ** です（担当タスク・進捗状況の記載・ステータス変更・成果・規模/負荷）。定型業務の内容・年休・スキルは載せません（負荷の数値＝月間負荷h・余力h のみ使用）。
- 件数・成果（年換算）・メンバー別の数値は **プログラムで集計** します（複数担当のタスクはチーム全体では1件として数えます）。AI には数値を計算させません。
- 期間内に動きの無い人も載せ、「今週の記載なし」と未完了の担当タスクを表示します（この人の分は AI を使いません）。
- AI（`instance/config.py` の `AI_〜`）が設定されていれば、各人の分（1人1回）とチーム全体（1回）を AI が見本どおりに整えます。AI が未設定・失敗した部分はルールベースの文章になり、文書に「AI未整形」と注記されます（AI は部分ごとに呼び出すため、一部が失敗しても他の部分は AI で整形されます）。

### 自動送信
- 設定した **曜日・時刻に1回だけ** 作成し、本番の宛先（`MAIL_TO` / `MAIL_CC`）へそのまま送信します（承認の手順はありません）。
- 動くのは `python serve.py` で起動したサーバーが動いている間だけです。サーバーが止まっている間に過ぎた分は、後から送信しません。
- 実行履歴は残さず、**前回の結果**（日時・きっかけ〔自動/手動/テスト〕・成否・メッセージ）だけを画面に表示します（毎回上書き）。

### 画面の設定項目
| 項目 | 内容 |
|------|------|
| 自動送信する | オン/オフ（既定はオフ） |
| 曜日・時刻 | 自動送信する曜日と時刻（既定: 月曜 08:00） |
| 対象期間のルール | 「送信日の前日までの7日間」（既定）／「送信日を含む7日間」。「送信日を含む7日間」では、送信日の送信時刻より後に記録した内容はどの自動送信の週報にも載りません（次回の期間は翌日から始まるため）。漏れなく載せたい場合は既定のルールを使ってください |
| 対象者 | 週報に載せる人（有効なユーザーから選択。全員選択/全解除あり）。チーム全体のまとめも選んだ人の担当タスクが対象。新しく登録したユーザーは自動では選ばれません。無効化したユーザーは選んでいても載りません |
| チーム全体の見本／個人の見本／書く際の注意点 | AI が見出し・順序・口調・分量を合わせる見本（見本に書いた事実は使いません）。見出しは「■」、箇条書きは「・」で始めます。差し込み記号 `{期間}` `{氏名}` `{作成日}` が使えます |
| ファイル名・メール件名のパターン | 既定は `週報_{開始日}-{終了日}.docx` と `【週報】{期間}`。画面に今日作成した場合のプレビューを表示 |
| メール本文 | 送信するメールの本文 |

ファイル名・件名・メール本文で使える差し込み記号:

| 記号 | 内容 |
|------|------|
| `{開始日}` `{終了日}` `{送信日}` | 日付（`yyyymmdd`） |
| `{年}` `{月}` | 対象期間の終了日の西暦年（4桁）・月（2桁） |
| `{週}` | 対象期間の終了日の ISO 週番号（2桁） |
| `{週の年}` | `{週}` の属する年（ISO 週の年・4桁）。年末年始は `{年}` と異なることがあるため、週番号と組み合わせるときはこちらを使います（例: `週報_{週の年}W{週}.docx`） |
| `{期間}` | `yyyy/mm/dd〜yyyy/mm/dd`（ファイル名では `/` を `-` に置き換え） |

ファイル名に使えない文字（`\ / : * ? " < > |` と制御文字）は `_` に置き換え、拡張子 `.docx` を付け、長さは120文字までに切り詰めます。

### 今すぐ作成
期間（開始・終了）を指定して、**Wordをダウンロード**／**テスト送信**（`MAIL_TEST_TO`、空なら差出人宛て。Cc なし）／**本番の宛先に送信**（確認あり）ができます。送信はバックグラウンドで行い、結果は「前回の結果」に表示されます。

### 保存場所（DB には保存しません）
- 画面の設定と前回の結果: `instance/weekly_settings.json`（Git 管理外。画面で保存したとき・送信したときに作成。無ければ既定値）。ファイルが壊れていて読み込めない場合は既定値（自動送信オフ）で動き、保存済みの内容を消さないよう上書きもしません（ログと画面の保存エラーに表示されるので、ファイルを修正するか削除してください）
- メールの送信サーバー・宛先・AI の接続先とキー: `instance/config.py`（画面では「設定あり/未設定」などを読み取り専用で表示）

## 期限超過通知（毎朝のメール）

マネージャーがナビの「**定期メール**」→「**期限超過通知**」から設定します（メンバーには表示されません）。
営業日の毎朝、期限を過ぎた未完了タスクの一覧を **1通のメール** で送ります（DB には何も保存しません）。

### メールの内容
- **期限超過** = 期限が今日より前で、完了していないタスク。状態で「未着手／進行中」と「保留」の2つの区分に分けます（完了したタスクは載せません）。
- 各区分の中は **担当者ごと** にまとめます。複数担当のタスクは各担当者の下に載せ、担当者がいないタスクは「担当者なし」にまとめます。無効化したユーザーが担当のタスクもその人の下に載せ、名前に「［無効］」を付けます（担当の付け替えが必要なことが分かるように）。
- 担当者は **件数の多い順**（同数なら表示名順）、タスクは **期限の古い順** に並べ、タスク名の横に期限（例: `期限 10/01`。今年以外は年も表示）を付けます。未着手／進行中の区分では状態も表示します。
- 各タスクに **直近の進捗記載（コメント）** を「表示するコメント件数」まで古い順に載せます。経過日数は土日祝を除いた営業日で数え（例: `3日前（土日祝除く）`、今日の記載は `本日`）、記載日と記載者を添えます。本文は1行にまとめ（改行は空白に）、長いものは約200文字で切ります。記載が無いタスクは「コメントなし」。
- 期限超過が0件の日も送信し、空の区分には「該当なし」と書きます。
- タスク名には **タスク詳細画面へのリンク**（`APP_BASE_URL` ＋ `/tasks/<ID>`）を付けます。`APP_BASE_URL` が空（または形式が不正）ならリンクは付けず、設定画面に警告を表示します。
- テキスト版とHTML版の両方を入れて送ります（`multipart/alternative`）。テキスト版はタスク名の後ろに括弧でURL、HTML版はタスク名がリンクになります（Outlook などでも読めるよう簡単な書式だけを使用）。
- 件名の例: `【期限超過】2026/10/05 未着手・進行中 3件／保留 1件`（件数はタスクの数。複数担当でも1件）

本文の形:
```
■未着手／進行中　期限超過一覧
Aさん（5件）
```

### 自動送信
- **営業日**（月〜金で、日本の祝日・振替休日・国民の休日でない日）の設定時刻に1回だけ送ります（既定 05:00）。土日・祝日は送りません。祝日はライブラリを使わずに法律のルールから計算します（`app/holidays.py`。春分・秋分は1980〜2099年の計算式）。独自の休業日（年末年始の休みなど）は考慮しません。
- 動くのは `python serve.py` で起動したサーバーが動いている間だけです。サーバーが止まっている間に過ぎた分は、後から送信しません。
- 宛先は `OVERDUE_MAIL_TO` / `OVERDUE_MAIL_CC`。`OVERDUE_MAIL_TO` が空なら週報と同じ `MAIL_TO` / `MAIL_CC` に送ります。
- 実行履歴は残さず、**前回の結果**（日時・きっかけ〔自動/手動/テスト〕・成否・メッセージ）だけを画面に表示します（毎回上書き）。

### 画面
| 項目 | 内容 |
|------|------|
| 自動送信する | オン/オフ（既定はオフ） |
| 送信時刻 | 自動送信の時刻（既定 05:00）。営業日だけ送信 |
| 表示するコメント件数 | 各タスクに載せる直近の進捗記載の件数（1〜10、既定 1） |
| 状況の表示 | 次回の自動送信日時（次の営業日。今日の時刻を過ぎていれば翌営業日）、前回の結果、メールの設定状況（使われる宛先を含む）、`APP_BASE_URL` の設定状況 |
| プレビュー | 今この時点のメールの内容（件名・HTML版・テキスト版） |
| テスト送信 | `MAIL_TEST_TO`（空なら差出人）宛てに今の内容を送信（Cc なし） |
| 今すぐ本番の宛先に送信 | 本番の宛先に今の内容を送信（確認あり） |

送信はバックグラウンドで行い、画面はすぐに戻ります（結果は「前回の結果」に表示）。

### 保存場所（DB には保存しません）
- 画面の設定と前回の結果: `instance/overdue_settings.json`（Git 管理外。画面で保存したとき・送信したときに作成。無ければ既定値）。読み込めない場合の扱いは週報と同じです（既定値〔自動送信オフ〕で動き、上書きしません）
- メールの送信サーバー・宛先・リンクの基準URL: `instance/config.py`（画面では読み取り専用で表示）

## スキルテスト

メンバーがナビの「**スキルテスト**」から受験します。マネージャーはナビの「**スキルテスト管理**」で受験履歴・問題プール・設定を管理します（マネージャーはスキル管理の対象外のため受験しません。メンバーは管理画面を開けません）。
AI が作った4択問題でテクニカルスキルの理解度を確かめ、結果に応じてスキルの到達度を **自動で登録** します。

### 出題
- 1回のテスト = 1つのスキル。対象は **有効なテクニカルスキル** だけです。判定するレベルは Lv1〜Lv4（設定「判定・自動登録するレベルの上限」とスキルの最大レベルの小さい方まで）。
- 問題数は既定で **30問**（Lv1 8問・Lv2 8問・Lv3 7問・Lv4 7問）。**やさしい順**（Lv1→Lv4）に1問ずつ出し、同じレベルの中はランダムな順です。選択肢の並びは受験ごとに入れ替えます。
- 1問ごとの制限時間は既定で Lv1 60秒・Lv2 90秒・Lv3 150秒・Lv4 180秒（合計 約58分）。0秒になると、その時点の選択で自動的に送信します（未選択なら時間切れ）。
- その人が **まだ見たことのない問題** を優先して出します。

### 判定と到達度の自動登録
- レベルLの **合格** = Lの正答率が合格ライン（既定 70%）以上 **かつ** Lより下のレベルがすべて合格。合格した最も高いレベルがテストの結果です（Lv1が不合格なら Lv0）。
- 結果のレベルが **今の到達度より高いときだけ**、既存の到達度（`skill_ratings`）に登録します。マネージャーが付けた到達度を下げることはありません。評価者は本人、メモは「スキルテストで自動登録（YYYY/MM/DD・正答率NN%）」です。登録した到達度はスキルマップ・個人スキル・Excel 出力にそのまま反映され、マネージャーは通常どおり編集で変更できます。
- 受験者が終了前にマネージャーになった・無効化された場合は登録しません。
- メンバーの結果画面には、**レベルごとの正解数・正答率・判定と結果のレベルだけ** を表示します（各問題の正解・解説は表示しません）。

### 受験のルールと不正の防止
- **正解はブラウザに送りません**（受験中も終了後も）。問題は1問ずつで、**前の問題には戻れません**。
- 制限時間は **サーバーで計ります**（問題を初めて表示した日時を保存。再読み込みしても残り時間は戻りません）。制限時間を5秒（通信の遅れの分）過ぎてから届いた回答は時間切れ（不正解）です。
- 途中で画面を閉じても、開き直すと続きから再開します。ただし **全体の期限**（各問の制限時間の合計＋10分）を過ぎた受験は、次に画面（一覧・出題・管理画面）を開いたときに自動で終了し、未回答を時間切れとして同じように採点・登録します（終了日時・登録日はその時ではなく全体の期限の日時になります）。
- 受験中のテストは1人1つ（受験中に別のスキルは始められません。開くと再開します）。同じスキルの **再受験は前回の受験開始から7日後** から（設定で変更可。0 なら制限なし）。
- ほかのタブ・ウィンドウへの切り替え（ブラウザの `visibilitychange` / `blur`）を **回数として記録** し、マネージャーが受験履歴と詳細（問題ごとの回数）で確認できます（ページの再読み込み・リンクでの画面移動は数えません）。
- 問題文の選択・コピー・右クリック・印刷を画面側で抑止します（軽い対策で、完全には防げません）。
- **防げないこと**: スマートフォンでの撮影、別の端末での検索、他人に代わりに受けてもらうことなど。離脱回数・問題ごとの所要時間は、結果を見るときの判断材料として使ってください。

### 問題プール（AIで作成）
- 問題は AI（`app/ai_client.py`。接続先は `instance/config.py` の `AI_〜`）が作成し、DB に保存して繰り返し使います。AIへの指示は「特定の組織に依存しない一般的な知識・技能を問う」「正解はちょうど1つ」「もっともらしい誤りの選択肢」「『すべて正しい』『どれでもない』は使わない」「JSONの配列だけを返す」です。レベルの意味（到達尺度の文言）を難易度として伝えます。
- AI の応答は厳しく検証し、条件を満たす問題だけを保存します（選択肢がちょうど4つで互いに異なり空でない・正解の位置が0〜3・長さの上限・既存の問題と内容が重複しない）。
- 受験の開始時に、その人が見たことのない問題が足りなければ、**その場で AI が不足分を作ります**（10問ずつ。1〜2分かかることがあり、画面に「問題を準備しています」と表示。待ち時間が長くなりすぎないよう、約2分半を過ぎたら新しい作成はしません）。AI が使えない・失敗した場合は、その人が以前に見た問題を **見たのが古い順に再出題** します（受験履歴の「再出題」に件数を記録）。それでも足りなければ「問題が準備できません。マネージャーに連絡してください」と表示し、受験を開始しません。
- マネージャーは「問題プール」で、スキル・レベルごとの問題数を確認し、**補充**（各レベルの有効な問題が目標数〔既定 20問〕になるまで AI で作成。バックグラウンドで実行し、結果は「前回の補充の結果」に表示）ができます。受験者を待たせないよう、事前の補充をおすすめします。
- AI の作った問題は誤りを含むことがあります。問題の一覧（正解・解説・出題回数・正解回数を表示）で確認し、不適切な問題は **無効** にしてください（今後は出題しません。受験履歴には出題時点の問題文・選択肢の控えが残ります）。

### 管理画面（マネージャー）
| 画面 | 内容 |
|------|------|
| 受験履歴 | 全員の受験（メンバー・スキル・状態で絞り込み、見出しで並び替え）。正解数・正答率・結果・到達度の登録（前→後）・離脱回数・再出題数。詳細では全問の問題文・選択肢（表示した順）・正解・本人の回答・所要時間・時間切れ・問題ごとの離脱回数・解説 |
| 問題プール | スキル・レベルごとの有効/無効の問題数、AI での補充、問題の一覧と無効化/有効に戻す |
| 設定 | 下の表の項目 |

| 設定項目 | 既定値 | 範囲 |
|------|------|------|
| 問題数（レベルごと） | Lv1 8・Lv2 8・Lv3 7・Lv4 7 | 1〜30 |
| 1問の制限時間（レベルごと） | Lv1 60秒・Lv2 90秒・Lv3 150秒・Lv4 180秒 | 10〜900秒 |
| 合格ライン（正答率） | 70% | 1〜100% |
| 再受験までの日数（前回の受験開始から） | 7日 | 0〜365日（0 は制限なし） |
| 判定・自動登録するレベルの上限 | Lv4 | Lv1〜4 |
| 問題プールの目標数（レベルごと。補充で使用） | 20問 | 1〜200問 |

設定を変えても、受験中・受験済みのテストは開始時の設定（受験ごとに控えを保存）のまま採点します。

### 4択テストで測れないこと（限界）
- 確かめられるのは、そのスキルの **知識と判断の一部** です。実際に作れるか（作業の速さ・品質・手順）、指導できるか・勉強会を開けるか（**Lv5・Lv6**）、**コンセプチュアルスキル・ヒューマンスキル** は測れないため、これまでどおりマネージャーが評価します。
- 4択はまぐれでも25%当たり、1レベルあたりの問題数も少ないため、結果には誤差があります。AI の問題の質・難易度にもばらつきがあります。自動登録は到達度を上げる方向にしか変えないので、実態と合わない場合はマネージャーが到達度を修正してください。

### 保存場所
- DB: 新しいテーブル `skill_test_questions`（問題プール）/ `skill_test_attempts`（受験）/ `skill_test_answers`（1問ごとの出題と回答）。起動時の `db.create_all()`（または `python migrate.py`）で自動作成され、**既存のテーブルは変更しません**。受験履歴は削除せずに残します。到達度の自動登録だけが既存の `skill_ratings` に行を追加・更新します。
- 画面の設定と前回の補充の結果: `instance/skilltest_settings.json`（Git 管理外。無ければ既定値。読み込めない場合の扱いは週報と同じ）。
- Excel: マネージャーダッシュボードの「Excelデータ出力」→「スキルテスト」（スキルテスト管理画面の「Excel出力」も同じ）で、受験履歴・全回答・問題の3シート。全データの出力にも含まれます。

## データベース

- **SQLite3**（`instance/app.db`。`instance/` は Git 管理外）。初回起動時に `db.create_all()` で自動生成されます。
- サンプルデータ投入は `python seed.py`（既存データがある場合は各テーブルごとにスキップ）。
- スキルテストのテーブル（`skill_test_questions` / `skill_test_attempts` / `skill_test_answers`）は新しいテーブルなので、既存の DB でも起動時に自動で追加されます（既存のテーブル・データは変更しません）。
- 以前の「報告書」機能のテーブル（`reports` / `report_tasks` / `report_templates` / `ai_settings`）は DB に残りますが、現在のコードからは使用しません（削除は不要です）。
- **既存テーブルへのカラム追加**は `db.create_all()` では反映されません。データを保持したままスキーマ変更する場合は `ALTER TABLE ... ADD COLUMN` を使用してください（本番データを消さないため）。まっさらに作り直す場合のみ `instance/app.db` を削除して `python seed.py`。

## 開発者向けメモ

**新しい機能の追加手順**
1. `app/models/` にモデルを追加し、`app/models/__init__.py` に import を追記
2. `app/<機能名>/routes.py` に Blueprint を作成
3. `app/__init__.py` の `register_blueprint` に追加
4. `app/templates/<機能名>/` に画面を追加、`app/templates/base.html` のナビにリンク追加

**ChatGPT-API（AI整形）の設定・移行**
接続情報は `instance/config.py` の `AI_API_URL` / `AI_API_KEY` / `AI_MODEL` / `AI_TIMEOUT` に記入します（Git 管理外のため、キーがリポジトリに入ることはありません）。`AI_API_URL` と `AI_API_KEY` がどちらも空なら機能は自動的に無効になり、週報はルールベースの文章のみ、スキルテストは問題プールにある問題だけで出題します。設定変更後はサーバーの再起動が必要です。
OpenAI互換のエンドポイント（自前のAPIなど）なら `AI_API_URL` をそのURLに変えるだけで移行できます。仕様が異なる場合は `app/ai_client.py` の `_call_chat_api()` の中身のみを書き換えてください（呼び出し側は `chat()` の戻り値 `(本文, エラー)` にしか依存していないため、他のコードは変更不要）。

**定期メールの追加**
メール送信は `app/mailer.py` の `send()`（テキスト版・HTML版・添付ファイル・宛先の指定に対応）、営業日の判定は `app/holidays.py` を使います。
自動送信は `app/scheduler.py` の `JOBS` にジョブ（設定の読み込み・実行時刻の判定・実行・失敗の記録）を追加します（スケジューラのスレッドは1本で、ジョブごとに実行済みの記録と例外処理を持ちます）。

**スキルテストの動作確認**
時刻は `app/models/skilltest.py` の `_now()` からだけ取っています（`app/skilltest/service.py` もこれを使用）。動作確認ではこの関数を差し替えると、制限時間・全体の期限・再受験の間隔を時刻を固定して確かめられます。AI の応答は `app/ai_client.py` の `_call_chat_api()` を差し替えて確認できます。

**本番LDAPへの移行**
`app/auth/ldap_client.py` の `authenticate()` 内「LDAP-API」ブロックのみを実 API 呼び出しに置き換えます。戻り値の形（`username / display_name / role / source`）は変更しないでください。固定ローカル管理者（`_LOCAL_ACCOUNTS`）とアプリ登録チェックはそのまま残します。
