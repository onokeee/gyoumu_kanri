# 業務管理システム

チームの業務を一元管理するための汎用Webアプリ（業務管理フレームワーク）です。
**タスク / 定型・定期業務 / スキル・業務（スキルテストを含む） / 年休** をここで管理し、メールやチャットでの連絡を最小化することを目指します。

- **技術**: Python 3.9 + Flask + SQLite3（Flask-SQLAlchemy / Flask-Login / Jinja2 / Bootstrap 5）
- **想定環境**: サーバーで常駐起動し、メンバーの PC からブラウザでアクセス
- **規模**: 小規模チーム向け（SQLite で十分な規模を想定）

## 主な機能

| 機能 | 概要 |
|------|------|
| **タスク管理** | 登録（マネージャーのみ）／一覧・絞り込み／詳細／編集／ステータス更新／削除。複数担当・開始日/期限・**規模（負荷の目安）**・**進捗状況**の記載・**成果（定量/定性）** に対応。完了にするには成果（実績）の入力が必要。開始日は期限と同じ日か前の日付だけ。メンバーは計画系項目（優先度/日付/規模/担当者）を変更不可。一覧のキーワード検索は200文字まで（超えた分は使わず、その旨を表示）。編集画面を開いた後に、ほかの操作（担当者の完了の登録・マネージャーの変更など）で変わった項目は、古い画面の保存で上書きしません（保存せずに「同時に変更された項目」を表示し、変わった項目を今の内容にした画面を出します）。タスク・定型業務を削除すると、その番号が次に登録したものに使われることがありますが、開いたままの画面のボタン（編集・状態の変更・進捗の記載・削除）や期限超過通知のリンクが、新しい別のタスク・業務を操作・表示することはありません（「削除されています」と表示、リンクは 404）。同時に押された削除・状態の変更（二度押し・2人が同時に操作）も内部エラーにせず、順番に処理します。 |
| **定型・定期業務** | 各自の繰り返し業務を管理（担当者/業務名/目的/回数/頻度/1回所要/内容/手順書状況）。全員が登録できます（メンバーは自分が担当のものだけを登録・編集。マネージャーはすべてを登録・編集）。削除はマネージャーのみ。ヒト別の件数・月間工数・手順書進捗のサマリー表つき。編集画面を開いた後にほかの操作で変わった項目は、タスクと同じく古い画面の保存で上書きしません。 |
| **スキル・業務** | スキルマップ（テクニカル/コンセプチュアル/ヒューマンの3区分）。横軸に **ヒト（到達度）** と **業務（必要スキル・レベル）** を任意に表示。別ビューで **業務×ヒトの対応可否表**、メンバー個別画面に **育成計画（業務対応に必要なスキルの過不足）**。マネージャーのみ。 |
| **スキルテスト** | メンバーが **有効なテクニカルスキル** ごとに、AI が作った4択問題（既定 30問・約58分）を受験。結果のレベル（Lv1〜4）が今の到達度より高ければ **到達度に自動で登録**（下がることはない）。1問ずつ・制限時間はサーバーで計測・正解はブラウザに送らない・画面から離れた回数を記録。マネージャーは受験履歴（全問の内容・回答・所要時間・離脱回数）・問題プール（AIで補充・問題の無効化）を管理（設定は「システム設定」）。詳しくは「[スキルテスト](#スキルテスト)」。 |
| **年休** | 承認なしの見える化。単日登録（全休/半休）、月カレンダー（土日色分け・同日上限の調整依頼）、取消・編集は本人のみ（無効化したメンバーの年休はマネージャーも取消できます。マネージャーダッシュボードの「直近1か月の休暇予定」には無効化したメンバーの年休を出しません）。 |
| **チーム管理** | チームマスタの追加/名称変更/有効無効、人×チームの紐づけ（兼務対応）、**メンバー（ユーザー）の追加・削除**。マネージャーのみ。固定ローカル管理者（`admin`）は削除・無効化できません（ログインのたびに有効に戻るため。ログインを止めるには `ADMIN_PASSWORD` を変更）。人を指すフォーム（削除・復帰のボタン、紐づけの表、タスク・定型業務の担当者、到達度の編集）は「ユーザーID＋ログインID」で送り、画面を開いた後に削除・追加で同じIDが別の人に再利用されていたら保存しません（「画面を開き直して」と表示）。紐づけの保存で変わるのは、画面を開いたときに表に出ていた人とチームの組み合わせだけです（後から追加した人・チームの紐づけは消えません）。業務データのあるメンバーの「削除」は無効化です（ログインできなくなり、担当者の選択肢・一覧から外れます。**担当中のタスク・定型業務は担当のまま残る**ため、必要なら担当を付け替えてください。チームの紐づけは外し、復帰しても戻らないため、復帰した後に「メンバーの紐づけ」で設定し直します）。 |
| **マネージャーダッシュボード** | チーム俯瞰（タスク進捗/直近1か月の休暇予定/スキル保有状況）、**ヒト別 負荷・案件状況**（タスク＋定型業務の月間工数を合算・余力表示）、メンバーの活動状況、**全タスクのガントチャート**（期間〔最長731日・約2年〕・担当者フィルタ・ステータス色分け・カミナリ線）。成果などの期間の日付の欄は、入力の途中で再読み込みしないよう「この期間で表示」ボタン（または Enter）で反映します（ダッシュボードの期間も同じ）。**AI分析（サマリーと推奨アクション）**: タスクの進捗・スキル状況・成果物の状況・各人の能力をまとめ、いま対応することを優先度順に表示（「AIで分析」で AI がコメントなどの本文を読み、課題の抽出・コメントへの対応の判定・書き直し案・各人の所見を加える）。詳しくは「[AI分析](#ai分析サマリーと推奨アクション)」。 |
| **週報（自動作成・メール送信）** | タスク情報から「チーム全体＋1人1ページ」の週報を Word で作成し、毎週決まった曜日・時刻にメールで自動送信。画面から今すぐ作成（ダウンロード/テスト送信/本番送信）も可能。AI（ChatGPT互換API）で文章を整形（未設定ならルールベース）。マネージャーのみ（ナビの「定期メール」。設定は「システム設定」）。詳しくは「[週報](#週報自動作成メール送信)」。 |
| **期限超過通知（毎朝のメール）** | 営業日（土日・祝日以外）の毎朝、期限を過ぎた未完了タスクの一覧を1通のメールで自動送信。状態（未着手／進行中・保留）ごと・担当者ごとにまとめ、直近の進捗記載とタスクへのリンクを付ける。画面でプレビュー・テスト送信・今すぐ送信も可能。マネージャーのみ（ナビの「定期メール」。設定は「システム設定」）。詳しくは「[期限超過通知](#期限超過通知毎朝のメール)」。 |
| **Excel データ出力** | 各メニューの全データ（現在＋履歴。スキルテストの受験履歴・全回答・問題を含む）を `.xlsx` で出力。マネージャーのみ。Excel に入れられない文字（改行・タブ以外の制御文字、U+FFFE/U+FFFF など）は除き、1つのセルの上限（32,767 文字）を超える値は上限までにして末尾に「…（以下省略…）」と書きます（全文はアプリの画面で確認）。 |
| **システム設定** | すべての設定を1画面（タブ）で変更。**基本設定**（`instance/config.py` の接続先・宛先・パスワードなど）／**週報**／**期限超過通知**／**スキルテスト**／**AI分析**。メール・AI の接続テストつき。マネージャーのみ。詳しくは「[システム設定](#システム設定)」。 |

### 役割（ロール）

**マネージャー（`manager`） / メンバー（`member`）** の2種類。マネージャーが全機能（スキル・スキルテスト管理・各ダッシュボード・チーム管理・データ出力・定期メール〔週報・期限超過通知〕・システム設定を含む）を利用でき、メンバーは一般利用（タスク/定型業務/年休）とスキルテストの受験が中心です。マネージャーはスキル管理の対象外のため、スキルテストは受験しません。

マネージャーのナビは、スキル・スキルテスト管理・マネージャーダッシュボード・チーム管理・システム設定を「**管理**」にまとめています（項目が多いため。幅 1200px 未満の画面ではメニューのボタンで開きます）。

## ファイル構成

Git で管理するファイルは、プロジェクト直下の次の6つだけです（サブフォルダはありません。`instance/` は実行時に作られる Git 管理外のフォルダです）。

```
業務管理/
├─ app.py             # Python のコードすべて（設定の既定値と見本・モデル・画面・定期メール・スケジューラ・flask コマンド）
├─ templates.html     # 画面テンプレート（Jinja2）・CSS・JavaScript・期限超過通知メールの HTML（ファイルごとのセクションにまとめたもの）
├─ ldap_client.py     # LDAP 認証（本番環境ごとに差し替えるファイル）
├─ README.md
├─ requirements.txt
├─ .gitignore
└─ instance/          # ※Git 管理外。初回の起動で自動作成
   ├─ app.db                   # SQLite DB
   ├─ config.py                # 環境ごとの設定（設定ファイルはこれ1つ。システム設定の画面からも変更）
   ├─ config.py.bak            # 画面から保存する直前の config.py（保存のたびに上書き）
   ├─ weekly_settings.json     # 週報の画面設定・前回の結果（保存・送信したときに作成）
   ├─ overdue_settings.json    # 期限超過通知の画面設定・前回の結果（保存・送信したときに作成）
   ├─ skilltest_settings.json  # スキルテストの画面設定・前回の補充の結果（保存・補充したときに作成）
   ├─ ai_analysis_settings.json  # AI分析のしきい値・1回に送る材料の文字数（保存したときに作成）
   ├─ ai_analysis.json         # AI分析の最新の結果（「AIで分析」が終わったときに作成・上書き）
   └─ scheduler.lock           # 定期メールの自動送信を1つのプロセスだけで動かすためのロック（flask run のときに作成）
```

## セットアップ

```bash
# 1.（推奨）仮想環境
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/Mac

# 2. 依存パッケージ
pip install -r requirements.txt

# 3. 初期データ（ダミーユーザー・サンプルデータ）の投入
flask --app app seed
```

- `flask` コマンドは **`app.py` のあるフォルダで実行** します（`--app app` は、今いるフォルダの `app.py` を指します）。`flask` が見つからない場合は、仮想環境を有効にするか、`python -m flask --app app ...` の形で実行します。
- 初回の起動（`seed` を含む）で、設定ファイル `instance/config.py` が自動作成されます。秘密鍵と管理者パスワードはこのとき自動生成されます。接続先などの設定は「[設定ファイル](#設定ファイルinstanceconfigpy)」を参照してください。

## 起動

```bash
# このPCだけで使う（ブラウザで http://127.0.0.1:8050 を開く）
flask --app app run --port 8050

# 同じネットワーク（LAN）の他の PC からも使う（サーバーでの通常の起動）
flask --app app run --host 0.0.0.0 --port 8050
```

- メンバーは `http://（サーバーのIPアドレス）:8050` でアクセスします（初めて LAN に公開するときは、Windows のファイアウォールでの許可が必要な場合があります）。
- 待ち受けのアドレス・ポートは **起動のコマンドの `--host` / `--port` だけ** で決まります。`--host` を省略すると `127.0.0.1`（このPCだけ）、`--port` を省略すると `5000` です。
- 止めるときは Ctrl+C です。
- **定期メール（週報・期限超過通知）の自動送信は、`flask --app app run` で起動している間だけ** 動きます（起動時に「定期メール（週報・期限超過通知）の自動送信スケジューラを起動しました。」と表示）。`seed` / `migrate` コマンドでは動きません。同じフォルダで2つ以上起動しても、自動送信を行うのは1つのプロセスだけです（`instance/scheduler.lock` のロック）。
- 起動時の `WARNING: This is a development server. ...` は、`flask run` で起動すると Flask が常に表示するメッセージです。

### 開発・動作確認（--debug）
```bash
flask --app app run --port 8050 --debug --exclude-patterns "*/instance/*"
```
- `--debug` を付けると、`app.py` などの `.py` ファイルを変更したときにサーバーが自動で再起動し、`templates.html` の変更も次の表示から反映されます。
- `--debug` ではエラーの画面から Python のコードを実行できるデバッガーが有効になります。**自分の PC での開発用です。`--host 0.0.0.0` と一緒に使わないでください。**
- `--exclude-patterns "*/instance/*"` は、システム設定の画面で `instance/config.py` を保存したときにサーバーが再起動しないようにする指定です（付けないと保存のたびに再起動します）。
- `--debug` のときは、ファイルの変更を見張るプロセスと画面を返すプロセスの2つが動き、自動送信は見張る側のプロセスで動きます。このプロセスは読み直されないため、コードや基本設定（`instance/config.py`）の変更を自動送信に反映するには、一度止めて起動し直してください。

### サーバーの起動時に自動で起動する
Windows の「タスク スケジューラ」でタスクを作り、「操作」を次のように設定します（「トリガー」は「コンピューターの起動時」など）。

| 項目 | 値 |
|------|------|
| プログラム/スクリプト | `flask.exe` の場所（仮想環境なら `（app.py のあるフォルダ）\.venv\Scripts\flask.exe`。それ以外はコマンド プロンプトで `where flask` を実行して確認） |
| 引数の追加 | `--app app run --host 0.0.0.0 --port 8050` |
| 開始（オプション） | `app.py` のあるフォルダ |

以前の版で `python serve.py`（または `waitress-serve ... --call app:create_app`）を登録していた場合は、この設定に置き換えてください（「[以前の版からの更新](#以前の版からの更新)」）。

## コマンド

どれも `app.py` のあるフォルダで実行します。

| コマンド | 内容 |
|------|------|
| `flask --app app run --port 8050`（LAN に公開するときは `--host 0.0.0.0` も） | サーバーとして起動（定期メールの自動送信もこのときだけ動く） |
| `flask --app app seed` | 初期データ（ダミーユーザー・サンプル）の投入。既にあるデータは作り直さない（テーブルごとにスキップ。既にあるユーザーの表示名・役割・有効/無効も変えない） |
| `flask --app app migrate` | 既存の DB に不足しているテーブル・列を追加（作成したテーブル・追加した列を表示。データは消さない。何度実行しても安全） |
| `flask --app app migrate --check` | 不足しているテーブル・列の確認だけ（テーブルの作成・列の追加をせず、DB を変更しない） |
| `flask --app app migrate --db パス` | `instance/app.db` 以外の既にある DB ファイルを対象にする（既定の DB には触れない。ファイルが無いときはエラーで止まり、新しい DB は作らない）。`--check --db パス` の最後に表示する「実行するには」のコマンドにも、同じ `--db "パス"` を付けます |
| `flask --app app --help` | 使えるコマンドの一覧 |

## ログインと認証

ログインは **①LDAP（本人確認）→ ②アプリ登録チェック** の2段階です。

1. **本人確認**: プロジェクト直下の `ldap_client.py` の `authenticate()`（現状はダミー実装）。本番はこの関数内の「LDAP-API」ブロックを実 API に差し替えるだけで移行できます（「[本番LDAPへの移行](#本番ldapへの移行)」）。
2. **アプリ登録チェック**: LDAP で本人確認できても、**アプリに登録済み・有効なユーザーでなければログインを拒否**します。新しいメンバーはマネージャーが「チーム管理 → メンバーの管理」で登録してからログイン可能になります。

- ログインの状態（セッション）は「ユーザーID＋ログインID」で覚えます。業務データの無いメンバーを削除すると、そのユーザーIDは次に追加した人に再利用されることがありますが、削除した人のブラウザに残ったログインの状態が別の人として使われることはありません（ログイン画面に戻ります）。この形式にした版へ更新した後は、全員が一度だけログインし直します。
- ログインの有効期限が切れた状態で保存・変更などのボタンを押した場合は、ログインの後、その操作の画面（上の階層の画面）に戻り、「直前の操作は行われていません」と表示します（もう一度操作してください）。
- 権限の無い画面（403）・見つからないページ（404。削除されたタスクへのメールのリンクなど）・画面として開けない URL（405）・想定外のエラー（500。内容はサーバーのログに残ります）は、日本語の案内とトップへのボタンを表示します。
- 認証サーバー（本番の `ldap_client.py` が問い合わせる LDAP認証API）が止まっている・つながらないときは、内部エラーの画面ではなく、ログイン画面に「認証サーバーに接続できなかったため、ログインできませんでした」と表示します（例外の内容はサーバーのログに残します。パスワードはログに出しません）。
- 保存・変更などの操作は、このアプリの画面から送られたものだけを受け付けます。ブラウザが付ける送信元（`Origin`、無ければ `Referer`）が、このアプリと同じ「http/https・ホスト・ポート」でなければ保存せずに 403 にします（同じサーバーの別のポートで動くほかの Web サービスの画面からの送信も断ります）。ほかのサイトの画面の中（iframe）には表示しません（`X-Frame-Options: SAMEORIGIN`）。
- 1回の送信（フォーム）は約50万バイト（日本語でおよそ5万字）までです。超えたときは入力が大きすぎる旨の画面を表示します（保存はされません。ブラウザの「戻る」で入力した画面に戻れます）。

### 固定ローカル管理者
LDAPとは独立に常に有効な管理者アカウントを1つ用意しています（初期設定・緊急用。本番でLDAPに差し替えても残ります）。

- ID: `admin` / パスワード: `instance/config.py` の `ADMIN_PASSWORD`
- パスワードは初回起動時に導入先ごとのランダムな値が自動で入ります。`instance/config.py` を開いて確認し、必要に応じて変更してください。
  変更は **システム設定の「基本設定」タブ** でもでき、保存するとすぐに有効になります（ファイルを直接編集した場合はサーバーの再起動で反映）。
- この確認はログインの処理（`app.py` の「5-1. 認証」）で、`ldap_client.py` より先に行います。`ADMIN_PASSWORD` が設定されている間は、`admin` はこの値でだけログインできます。
- `ADMIN_PASSWORD` を空にすると、`admin` の確認も `ldap_client.py` の `authenticate()` に任せます（`ldap_client.py` に `admin` 用の固定パスワードがある場合は、それでログインできるようになります。同梱の `ldap_client.py` には既定の固定パスワードがあるため、**空にしても admin のログインは無効になりません**）。
- 以前の版で自動作成した `instance/config.py` には、`ADMIN_PASSWORD` の説明に「空にすると admin でのログインは無効になります」と書かれていますが、これは誤りです（上のとおり `ldap_client.py` の判定になります）。ファイルのコメントは自動では直らないため、必要ならこの行を書き換えてください（動作には影響しません）。

### 動作確認用ダミーアカウント（開発用。本番LDAP導入で不要）
`kacho`（マネージャー）/ `leader`・`yamada`・`suzuki`・`tanaka`（メンバー）。パスワードはすべて `password`。

## 設定ファイル（instance/config.py）

環境によって変わる値（秘密鍵・管理者パスワード・LDAP / AI / メールの接続先など）は、すべて **`instance/config.py` の1ファイル** にまとめて記入します。設定ファイルはこれだけです。

- `instance/config.py` は DB（`instance/app.db`）と同じフォルダにあり、**Git 管理外** です。パスワードやキーがリポジトリに入ることはありません。
- ファイルが無い状態で起動すると（`flask --app app run` / `seed` / `migrate`。`migrate --db` を除く）、`app.py` の中の見本 **`CONFIG_TEMPLATE`** をもとに **自動作成** されます（既にあるファイルが上書きされることはありません）。作成時は場所だけが画面（コンソール）に表示されます。
  - `SECRET_KEY` と `ADMIN_PASSWORD` にはランダムな値が自動で入ります。
  - 以前の「AI接続設定」画面で保存した接続先・APIキー・モデルが DB に残っている場合は、作成時に **1回だけ** `AI_API_URL` / `AI_API_KEY` / `AI_MODEL` に引き継ぎます（DB は読み取り専用で開き、変更しません）。
- **マネージャーは画面（システム設定の「基本設定」タブ）から変更できます**（詳しくは「[システム設定](#システム設定)」）。画面で保存すると変更した項目の行だけが書き換わり、`SECRET_KEY` 以外はすぐに反映されます。
- これまでどおり **直接編集することもできます**。書式は Python です（文字列は `"..."`、アドレスの一覧は `[...]`）。直接編集した値は **サーバーを再起動** すると反映されます。
- ファイルに書かれていない項目は `app.py` の既定値（`Config`）が使われます。後から追加された項目（例: `APP_BASE_URL`）は、既にある `instance/config.py` には自動では追記されません。画面で値を変更して保存すると、その項目がファイルの末尾に追記されます（直接編集する場合は下の表か `app.py` の `CONFIG_TEMPLATE` を参考に書き足してください）。
- **アプリは環境変数を読みません**（設定はこのファイルだけで完結します）。ただし `flask` コマンドは、python-dotenv が入っていると `.env` を自動で読み込みます。以前の版の `.env` が残っている場合は、移動または削除してください（「[以前の版からの更新](#以前の版からの更新)」）。
- 以前の版の次の項目は使わなくなりました。ファイルに残っていても動作には影響せず、システム設定の「基本設定」タブの「その他」に「**未使用**」と表示されます。「**未使用の設定を削除**」ボタンで、その行をまとめて削除できます（「[基本設定](#基本設定instanceconfigpy)」）。
  - `SERVER_HOST` / `SERVER_PORT`: 待ち受けのアドレス・ポートは起動のコマンドの `--host` / `--port` で指定します
  - `MAIL_USE_TLS` / `MAIL_USERNAME` / `MAIL_PASSWORD`: メールは暗号化（STARTTLS）・認証（ログイン）なしで送信します
  - `MAIL_TEST_TO`: テスト送信・メール接続テストは差出人（`MAIL_FROM`）宛てに送ります
  - `OVERDUE_MAIL_TO` / `OVERDUE_MAIL_CC`: 期限超過通知は週報と同じ `MAIL_TO` / `MAIL_CC` に送ります

| 項目 | 用途 | 既定値 |
|------|------|------|
| `SECRET_KEY` | セッション暗号化キー（自動作成時にランダム生成）。空なら起動ごとに一時的な鍵を使用（再起動でログアウト） | 空 |
| `ADMIN_PASSWORD` | 固定ローカル管理者 `admin` のパスワード（自動作成時にランダム生成）。空なら `admin` の確認は `ldap_client.py` に任せる | 空 |
| `LDAP_API_URL` | LDAP認証APIのURL（本番で使用） | 空 |
| `AI_API_URL` | ChatGPT（OpenAI互換）APIのエンドポイント。空なら OpenAI 公式 | 空 |
| `AI_API_KEY` | APIキー。`AI_API_URL` とどちらも空ならAIは使わない（週報はルールベースで作成、スキルテストは問題プールにある問題だけで出題） | 空 |
| `AI_MODEL` | 使用するモデル名 | `gpt-4o-mini` |
| `AI_TIMEOUT` | AIの応答待ちタイムアウト（秒） | `60` |
| `MAIL_SMTP_SERVER` | メール送信サーバー（ホスト名またはIPアドレス）。空ならメール送信不可。暗号化・認証なしで送信するため、認証なしで送信できるサーバーを指定 | 空 |
| `MAIL_SMTP_PORT` | 送信サーバーのポート番号 | `25` |
| `MAIL_FROM` | 差出人アドレス。テスト送信・メール接続テストはこのアドレス宛てに送る | 空 |
| `MAIL_TO` / `MAIL_CC` | 宛先（To）・同報（Cc）のアドレス一覧（週報・期限超過通知の両方に使う） | `[]` |
| `APP_BASE_URL` | メールに載せるタスクへのリンクの基準URL（メンバーの PC からこのアプリを開くときの URL。末尾の `/` は不要）。空ならリンクなし（タスク名だけ） | 空 |

記入例（値はすべて例です）:
```python
AI_API_KEY = "sk-..."                      # OpenAI公式を使う場合
MAIL_SMTP_SERVER = "smtp.example.com"
MAIL_FROM = "noreply@example.com"
MAIL_TO = ["manager@example.com"]
APP_BASE_URL = "http://192.0.2.10:8050"    # メールのリンク用（サーバーのアドレスと起動時の --port）
```

メールの送信方法: `smtplib.SMTP(MAIL_SMTP_SERVER, MAIL_SMTP_PORT, timeout=20)` で接続し、`sendmail(MAIL_FROM, MAIL_TO＋MAIL_CC, メッセージ)` で送ります（**暗号化〔STARTTLS〕・認証〔ログイン〕は行いません**）。メッセージには `Date`・`Message-ID` を付け、HTML版がある場合は `multipart/alternative`（テキスト版＋HTML版）、週報は Word ファイルを添付します。テスト送信は差出人（`MAIL_FROM`）だけに送ります（Cc なし）。`sendmail` に渡す宛先は表示名を外したアドレスで、To と Cc に同じアドレスがある場合（「表示名 <アドレス>」とアドレスだけの書き方、大文字・小文字の違いを含む）は1通だけ届けます（ヘッダの To / Cc は設定どおり）。

## システム設定

マネージャーがナビの「**システム設定**」（`/system/settings`）から、アプリのすべての設定を1つの画面で変更します（メンバーには表示されず、URL を直接開いても 403。未ログインならログイン画面）。

### タブ
タブごとにフォームと保存ボタンが分かれていて、保存したタブの内容だけが保存されます。開いているタブは URL（`?tab=config` / `weekly` / `overdue` / `skilltest` / `analysis`。`#weekly` のような指定も可）に残るので、再読み込み・保存後も同じタブが開きます。

| タブ | 内容 | 保存先 |
|------|------|------|
| 基本設定（config） | 環境ごとの設定（「[設定ファイル](#設定ファイルinstanceconfigpy)」の表の項目）。メール・AI の接続テスト | `instance/config.py` |
| 週報 | 自動送信する/しない・曜日・時刻・対象期間のルール・対象者・文章の見本と注意点・ファイル名/件名のパターン・メール本文 | `instance/weekly_settings.json` |
| 期限超過通知 | 自動送信する/しない・送信時刻・表示するコメント件数 | `instance/overdue_settings.json` |
| スキルテスト | レベルごとの問題数・制限時間、合格ライン、再受験までの日数、判定・自動登録するレベルの上限、問題プールの目標数 | `instance/skilltest_settings.json` |
| AI分析 | 期限が近いとみなす営業日数（N1）・記載がないとみなす営業日数（N2）・1回に送る材料の最大文字数 | `instance/ai_analysis_settings.json` |

各機能の画面には、実行と状況の表示だけが残ります（設定へは各画面の「設定はシステム設定で変更」のリンクから移動できます）。

| 機能の画面 | 残っているもの |
|------|------|
| 週報（`/weekly/`） | 次回の自動送信・前回の結果・メール/AI の設定状況・今すぐ作成（ダウンロード/テスト送信/本番送信）・現在の設定の概要（ファイル名/件名のプレビュー） |
| 期限超過通知（`/overdue/`） | 次回の自動送信・前回の結果・メール/リンクの設定状況・今すぐ送信（テスト/本番）・現在の設定の概要・メールのプレビュー |
| スキルテスト管理（`/skilltest/admin`） | 受験履歴・問題プール |

以前の設定の URL（`POST /weekly/settings`・`POST /overdue/settings`・`/skilltest/admin/settings`）は、システム設定の該当タブ（またはその保存）へ転送されます。

### 基本設定（instance/config.py）
- 項目は「ログイン・セキュリティ / LDAP / AI / メール送信 / 宛先 / リンク」に分けて表示します。項目の定義（表示名・説明・種類・再起動の要否・秘密かどうか）は `app.py` の `FIELDS`（「10-1」）の1か所にあります。定義の無い項目（`app.py` の見本・既定値にだけある項目、`instance/config.py` にだけ書かれている項目、`instance/config.py` で上書きした固定設定〔`APP_NAME` / `SESSION_COOKIE_SAMESITE` など〕）は「**その他**」に読み取り専用で表示されます（画面から変更できない項目が黙って抜け落ちないように）。以前の版の項目（`SERVER_HOST` / `SERVER_PORT` / `MAIL_USE_TLS` / `MAIL_USERNAME` / `MAIL_PASSWORD` / `MAIL_TEST_TO` / `OVERDUE_MAIL_TO` / `OVERDUE_MAIL_CC`）が残っている場合は、ここに「**未使用**」と使わない理由を表示します（自動ではファイルから消しません）。
- **設定ファイルが無いとき**: サーバーの実行中に `instance/config.py` を削除・名前の変更をした場合は、画面上部に「設定ファイルがありません」と表示し、基本設定は **保存できません**（実行中の値を表示します）。一部の項目だけのファイルができたり、実行中の設定が既定値〔空の admin のパスワードなど〕に戻ったりしないようにするためです。サーバーを再起動すると見本から自動作成されます。
- **未使用の設定を削除**: 「その他」に未使用の項目があるとき、マネージャーは「未使用の設定を削除」（確認あり）で、`instance/config.py` からその項目の行を削除できます。行のすぐ上に続くコメント（その項目の説明）も、説明している項目がすべて削除されるときだけ一緒に削除します（ほかの項目と一緒に書かれた説明は残します。前後の空行は1つにまとめます）。保存と同じく、削除後の内容が正しく読み込めてほかの項目の値が変わらないことを確かめてから、変更前のファイルを `instance/config.py.bak` に残して置き換えます。単純な `KEY = 値` 以外の書き方の項目は削除せず、直接編集するよう表示します。
- 入力の確認: URL は `http://` / `https://`（空も可。ID・パスワードを含む `https://user:pass@host/` の形は不可。`APP_BASE_URL` は「?」「#」を含めない〔`…/?`・`…/#` のように末尾だけでも不可〕）、送信サーバーはホスト名・IPv4 アドレス・IPv6 アドレス（`[ ]` なし）だけ（`smtp.example.com:587` のようにポート番号を付けた値は不可。ポート番号は「ポート番号」の欄）、ポートは 1〜65535、`AI_TIMEOUT` は 5〜600 秒、`AI_API_URL` と `AI_API_KEY` は半角英数字・記号だけ（AI の呼び出しは URL・キーに全角の文字・日本語を含められないため。日本語のドメイン・パスはピュニコード・パーセントエンコードにしたもの）、アドレスの一覧は1行に1件（「,」「;」区切りも可。`name@example.com` の形式を確認）、改行・制御文字は不可。誤りが1つでもあれば **何も保存せず**、入力中の内容（パスワード・キーを除く）を残してメッセージを表示します。
- **保存の仕組み**: 変更した項目の `KEY = ...` の行だけを書き換え（ファイルに無い項目は末尾に追記）、コメント・ほかの項目・書式はそのまま残します。先頭に「`# 最終更新: YYYY-MM-DD HH:MM（画面から変更: ユーザー名）`」の1行を付けます（毎回置き換え）。書き換え後の内容が正しく読み込めて期待どおりの値になることを確かめてから、**変更前のファイルを `instance/config.py.bak` にコピー**し、一時ファイル経由で置き換えます（`.bak` は直前の1世代だけで、保存のたびに上書き。パスワード・キーも含むので扱いに注意）。画面を開いた後にファイルが変わっていた場合（ほかの人の保存・直接の編集）は保存せず、最新の内容を表示します。
- **すぐに反映される項目**: `SECRET_KEY` 以外は、保存と同時に実行中のアプリにも反映されます（メール・AI・リンク・admin のパスワードなど）。`LDAP_API_URL` をどう使うかは `ldap_client.py` の実装によります。
- **再起動が必要な項目**: `SECRET_KEY` はファイルにだけ保存され、サーバーの再起動後に反映されます。ファイルの値と実行中の値が違う項目があるあいだ、画面上部に「**再起動が必要な変更があります**」と項目名を表示します（ファイルを直接編集した場合も同じ）。
- **秘密の値**（`SECRET_KEY` / `ADMIN_PASSWORD` / `AI_API_KEY`）: 画面には「設定あり／未設定」だけを表示し、値は HTML・ログ・メッセージのどこにも出しません。入力欄を **空欄のまま保存すると変更しません**。ただし接続先（`AI_API_URL` のホスト・ポート・http/https）を変えるときは、保存済みのキーを新しい接続先へ送らないよう、`AI_API_KEY` を入力し直すか「空にする」を指定します。空にするときは「**空にする**」にチェックします（`ADMIN_PASSWORD` を空にすると admin のログイン可否は `ldap_client.py` の判定に任されます）。`ADMIN_PASSWORD` の変更は確認のため2回入力します（8文字以上）。`SECRET_KEY` は自由に入力できず、「**新しいキーを生成**」でランダムな値（`secrets.token_hex(32)`）を作ります。新しいキーは再起動後に有効になり、そのとき **全員がログアウト** されます。
- **接続テスト**: 「メール接続テスト」は差出人（`MAIL_FROM`）宛てに短いテキストのメールを1通送り（送信サーバーに断られたときは、サーバーの応答〔コードと本文。例: `530 5.7.57 …`〕と、分かる場合は原因〔ログイン・暗号化が必要なサーバー、このPCからの中継が許可されていないなど〕を表示します。接続できても応答が無いときは、ポート番号の確認を案内します〔465 などの暗号化した接続には対応していません〕。週報・期限超過通知の送信の結果も同じ）、「AI接続テスト」は AI に短い問い合わせを1回送ります。どちらも **保存済みの設定（実行中の値）** を使い、結果（OK またはエラー。パスワード・キーは伏せ字。AI の応答は伏せ字にしてから80文字までに短くする）を画面に表示します。
- `instance/config.py` は **これまでどおり直接編集してもかまいません**（直接編集した値はサーバーの再起動で反映）。

## 週報（自動作成・メール送信）

マネージャーがナビの「**定期メール**」→「**週報**」から、今すぐ作成・前回の結果の確認を行います。曜日・時刻・対象者・見本などの設定は「**システム設定**」の「**週報**」タブで変更します（メンバーには表示されません）。

### 作成される週報
- 1回の作成で **Word ファイル1つ**。構成は「タイトル・対象期間」→「**チーム全体**」のまとめ（文章＋メンバー別の集計表）→ 改ページして **1人1ページ** の個人分。
- 材料は **タスク情報だけ** です（担当タスク・進捗状況の記載・ステータス変更・成果・規模/負荷）。定型業務の内容・年休・スキルは載せません（負荷の数値＝月間負荷h・余力h のみ使用）。
- 件数・成果（年換算）・メンバー別の数値は **プログラムで集計** します（複数担当のタスクはチーム全体では1件として数えます）。AI には数値を計算させません。
- **期限超過** は、未完了で期限が「期間の最終日の翌日」と「作成した日」の早いほうより前のタスクです。「送信日を含む7日間」のように期間が作成日（送信日）を含むときも、今日が期限のタスクは期限超過にせず「期限が近い」に入れます（期限超過通知・ダッシュボードと同じく、期限が今日より前のものだけが期限超過）。
- 期間内に動きの無い人も載せ、「今週の記載なし」と未完了の担当タスクを表示します（この人の分は AI を使いません）。
- タスクの開始日・期限は `mm/dd`（期間の最終日と違う年は `yyyy/mm/dd`。前の年からの期限超過が数日の遅れに見えないように）で書きます（Word・AI に渡す材料とも）。記載・完了・状態の変更の日付は期間の中のため `mm/dd` です。
- AI（システム設定の「基本設定」タブ＝`instance/config.py` の `AI_〜`）が設定されていれば、各人の分（1人1回）とチーム全体（1回）を AI が見本どおりに整えます。AI が未設定・失敗した部分はルールベースの文章になり、文書に「AI未整形」と注記されます（AI は部分ごとに呼び出すため、一部が失敗しても他の部分は AI で整形されます）。

### 自動送信
- 設定した **曜日・時刻に1回だけ** 作成し、本番の宛先（`MAIL_TO` / `MAIL_CC`）へそのまま送信します（承認の手順はありません）。実行した日付・時刻の印を `instance/weekly_settings.json`（`last_auto_key`）に残すため、その時刻の1分の間にサーバーを再起動しても2回は送りません。
- 動くのは `flask --app app run` で起動したサーバーが動いている間だけです。サーバーが止まっている間に過ぎた分は、後から送信しません。
- 実行履歴は残さず、**前回の結果**（日時・きっかけ〔自動/手動/テスト〕・成否・メッセージ）だけを画面に表示します（毎回上書き）。

### 設定項目（システム設定の「週報」タブ）
| 項目 | 内容 |
|------|------|
| 自動送信する | オン/オフ（既定はオフ） |
| 曜日・時刻 | 自動送信する曜日と時刻（既定: 月曜 08:00） |
| 対象期間のルール | 「送信日の前日までの7日間」（既定）／「送信日を含む7日間」。「送信日を含む7日間」では、送信日の送信時刻より後に記録した内容はどの自動送信の週報にも載りません（次回の期間は翌日から始まるため）。漏れなく載せたい場合は既定のルールを使ってください |
| 対象者 | 週報に載せる人（有効なユーザーから選択。全員選択/全解除あり）。チーム全体のまとめも選んだ人の担当タスクが対象。新しく登録したユーザーは自動では選ばれません。無効化したユーザーは選んでいても載りません（無効のあいだはここに表示されませんが、このタブを保存しても選択は残り、復帰すると対象に戻ります） |
| チーム全体の見本／個人の見本／書く際の注意点 | AI が見出し・順序・口調・分量を合わせる見本（見本に書いた事実は使いません）。見出しは「■」、箇条書きは「・」で始めます。差し込み記号 `{期間}` `{氏名}` `{作成日}` が使えます |
| ファイル名・メール件名のパターン | 既定は `週報_{開始日}-{終了日}.docx` と `【週報】{期間}`。今日作成した場合のプレビューを表示（週報の画面にも表示）。パターンはファイル名 200文字・件名 300文字まで（見本・注意点・メール本文は 20000文字まで。超えたときは保存せずに表示） |
| メール本文 | 送信するメールの本文 |

ファイル名・件名・メール本文で使える差し込み記号:

| 記号 | 内容 |
|------|------|
| `{開始日}` `{終了日}` `{送信日}` | 日付（`yyyymmdd`） |
| `{年}` `{月}` | 対象期間の終了日の西暦年（4桁）・月（2桁） |
| `{週}` | 対象期間の終了日の ISO 週番号（2桁） |
| `{週の年}` | `{週}` の属する年（ISO 週の年・4桁）。年末年始は `{年}` と異なることがあるため、週番号と組み合わせるときはこちらを使います（例: `週報_{週の年}W{週}.docx`） |
| `{期間}` | `yyyy/mm/dd〜yyyy/mm/dd`（ファイル名では `/` を `-` に置き換え） |

ファイル名に使えない文字（`\ / : * ? " < > |` と制御文字）は `_` に置き換え、拡張子 `.docx` を付け、長さは120文字までに切り詰めます。

### 今すぐ作成（週報の画面）
期間（開始・終了）を指定して、**Wordをダウンロード**／**テスト送信**（差出人〔`MAIL_FROM`〕宛て。Cc なし）／**本番の宛先に送信**（確認あり）ができます。送信はバックグラウンドで行い、結果は「前回の結果」に表示されます。期間は366日以内で、終わりの日は 9999/12/23 まで（それより後は入力の誤りとして断ります）。
各人の月間負荷・余力は、マネージャーダッシュボードの「ヒト別 負荷・案件状況」と同じ計算です（複数担当のタスクは有効な担当者の数で均等割り。対象に選んだ人によって値は変わりません）。
Word ファイルのプロパティの作成者・最終更新者はアプリの名前（`APP_NAME`）、作成日時・更新日時は作成した日時です。

### 保存場所（DB には保存しません）
- 画面の設定と前回の結果: `instance/weekly_settings.json`（Git 管理外。画面で保存したとき・送信したときに作成。無ければ既定値）。ファイルが壊れていて読み込めない場合は既定値（自動送信オフ）で動き、保存済みの内容を消さないよう上書きもしません。週報の画面とシステム設定の「週報」タブにその旨を表示し、今すぐ作成・送信もできなくなります（ファイルを修正するか削除してください）
- メールの送信サーバー・宛先・AI の接続先とキー: `instance/config.py`（システム設定の「基本設定」タブで変更。週報の画面では「設定あり/未設定」などを読み取り専用で表示）

## 期限超過通知（毎朝のメール）

マネージャーがナビの「**定期メール**」→「**期限超過通知**」から、プレビュー・今すぐ送信・前回の結果の確認を行います。自動送信・時刻・コメント件数の設定は「**システム設定**」の「**期限超過通知**」タブで変更します（メンバーには表示されません）。
営業日の毎朝、期限を過ぎた未完了タスクの一覧を **1通のメール** で送ります（DB には何も保存しません）。

### メールの内容
- **期限超過** = 期限が今日より前で、完了していないタスク。状態で「未着手／進行中」と「保留」の2つの区分に分けます（完了したタスクは載せません）。
- 各区分の中は **担当者ごと** にまとめます。複数担当のタスクは各担当者の下に載せ、担当者がいないタスクは「担当者なし」にまとめます。無効化したユーザーが担当のタスクもその人の下に載せ、名前に「［無効］」を付けます（担当の付け替えが必要なことが分かるように）。
- 担当者は **件数の多い順**（同数なら表示名順）、タスクは **期限の古い順** に並べ、タスク名の横に期限（例: `期限 10/01`。今年以外は年も表示）を付けます。未着手／進行中の区分では状態も表示します。
- 各タスクに **直近の進捗記載（コメント）** を「表示するコメント件数」まで古い順に載せます。経過日数は土日祝を除いた営業日で数え（例: `3日前（土日祝除く）`、今日の記載は `本日`。土日祝に送ったときなど、営業日で数えると0日になる過去の記載は暦日で `2日前` のように表示）、記載日と記載者を添えます。コメントはタスク名の次の行から1件ずつ書き、本文は1行にまとめ（改行は空白に）、長いものは約200文字で切ります。記載が無いタスクは「コメントなし」。
- 期限超過が0件の日も送信し、空の区分には「該当なし」と書きます。
- タスク名には **タスク詳細画面へのリンク**（`APP_BASE_URL` ＋ `/tasks/<ID>`）を付けます。`APP_BASE_URL` が空（または形式が不正）ならリンクは付けず、期限超過通知の画面に警告を表示します（前回の結果にも「リンクなし」と残ります）。
- テキスト版とHTML版の両方を入れて送ります（`multipart/alternative`）。テキスト版はタスク名の後ろに括弧でURL、HTML版はタスク名がリンクになります（Outlook などでも読めるよう簡単な書式だけを使用）。
- 件名の例: `【期限超過】2026/10/05 未着手・進行中 3件／保留 1件`（件数はタスクの数。複数担当でも1件）

本文の形:
```
■未着手／進行中　期限超過一覧
Aさん（5件）
　タスク名（リンク）［進行中・期限 10/01］
　　【3日前（土日祝除く） 09/30 A】直近の進捗記載
...
■保留　期限超過一覧
Bさん（2件）
　タスク名（リンク）［期限 09/20］
　　コメントなし
```

### 自動送信
- **営業日**（月〜金で、日本の祝日・振替休日・国民の休日でない日）の設定時刻に1回だけ送ります（既定 05:00。実行した日付・時刻の印を `instance/overdue_settings.json` の `last_auto_key` に残すため、その1分の間にサーバーを再起動しても2回は送りません）。土日・祝日は送りません。祝日はライブラリを使わずに法律のルールから計算します（`app.py` の「2-4. 営業日カレンダー」。春分・秋分は1980〜2099年の計算式）。独自の休業日（年末年始の休みなど）は考慮しません。
- 動くのは `flask --app app run` で起動したサーバーが動いている間だけです。サーバーが止まっている間に過ぎた分は、後から送信しません。
- 宛先は週報と同じ `MAIL_TO` / `MAIL_CC` です。
- 実行履歴は残さず、**前回の結果**（日時・きっかけ〔自動/手動/テスト〕・成否・メッセージ）だけを画面に表示します（毎回上書き）。

### 設定項目（システム設定の「期限超過通知」タブ）
| 項目 | 内容 |
|------|------|
| 自動送信する | オン/オフ（既定はオフ） |
| 送信時刻 | 自動送信の時刻（既定 05:00）。営業日だけ送信 |
| 表示するコメント件数 | 各タスクに載せる直近の進捗記載の件数（1〜10、既定 1） |

### 画面（期限超過通知の画面）
| 項目 | 内容 |
|------|------|
| 状況の表示 | 次回の自動送信日時（次の営業日。今日の時刻を過ぎていれば翌営業日）、前回の結果、メールの設定状況（使われる宛先を含む）、`APP_BASE_URL` の設定状況 |
| プレビュー | 今この時点のメールの内容（件名・HTML版・テキスト版） |
| テスト送信 | 差出人（`MAIL_FROM`）宛てに今の内容を送信（Cc なし） |
| 今すぐ本番の宛先に送信 | 本番の宛先に今の内容を送信（確認あり） |

送信はバックグラウンドで行い、画面はすぐに戻ります（結果は「前回の結果」に表示）。

### 保存場所（DB には保存しません）
- 画面の設定と前回の結果: `instance/overdue_settings.json`（Git 管理外。画面で保存したとき・送信したときに作成。無ければ既定値）。読み込めない場合の扱いは週報と同じです（既定値〔自動送信オフ〕で動き、上書きしません。期限超過通知の画面とシステム設定の「期限超過通知」タブにその旨を表示し、今すぐ送信もできなくなります）
- メールの送信サーバー・宛先・リンクの基準URL: `instance/config.py`（システム設定の「基本設定」タブで変更。期限超過通知の画面では読み取り専用で表示）

## スキルテスト

メンバーがナビの「**スキルテスト**」から受験します。マネージャーはナビの「**スキルテスト管理**」で受験履歴・問題プールを管理し、設定は「**システム設定**」の「**スキルテスト**」タブで変更します（マネージャーはスキル管理の対象外のため受験しません。メンバーが貼ったリンクなどでマネージャーが受験の画面を開いたときは、スキルテスト管理の受験の詳細〔または受験履歴〕を表示します。メンバーは管理画面を開けません）。
AI が作った4択問題でテクニカルスキルの理解度を確かめ、結果に応じてスキルの到達度を **自動で登録** します。

### 出題
- 1回のテスト = 1つのスキル。対象は **有効なテクニカルスキル** だけです。判定するレベルは Lv1〜Lv4（設定「判定・自動登録するレベルの上限」とスキルの最大レベルの小さい方まで。上限を下げると、メンバーの画面・管理画面の説明のレベルもそれに合わせて変わります）。
- 問題数は既定で **30問**（Lv1 8問・Lv2 8問・Lv3 7問・Lv4 7問）。**やさしい順**（Lv1→Lv4）に1問ずつ出し、同じレベルの中はランダムな順です。選択肢の並びは受験ごとに入れ替えます。
- 1問ごとの制限時間は既定で Lv1 60秒・Lv2 90秒・Lv3 150秒・Lv4 180秒（合計 約58分）。0秒になると、その時点の選択で自動的に送信します（未選択なら時間切れ）。
- その人が **まだ見たことのない問題** を優先して出します（ほかの問題の作成〔補充など〕を待っている間に保存された問題も、見たことがなければ再出題より先に使います）。
- 出題の画面の「全体の期限」は日付と時刻で表示します（夜に始めたときなど、期限が翌日になることがあるため）。

### 判定と到達度の自動登録
- レベルLの **合格** = Lの正答率が合格ライン（既定 70%）以上 **かつ** Lより下のレベルがすべて合格。合格した最も高いレベルがテストの結果です（Lv1が不合格なら Lv0）。
- 結果のレベルが **今の到達度より高いときだけ**、既存の到達度（`skill_ratings`）に登録します。マネージャーが付けた到達度を下げることはありません。評価者は本人、メモは「スキルテストで自動登録（YYYY/MM/DD・正答率NN%）」です（それまでのメモ〔マネージャーが書いたもの〕は消さずに「 ／ 以前のメモ: …」として後ろに残します。200文字に入りきらない分は切り詰めます）。登録した到達度はスキルマップ・個人スキル・Excel 出力にそのまま反映され、マネージャーは通常どおり編集で変更できます。
- 受験者が終了前にマネージャーになった・無効化された場合と、受験中にそのスキルが無効化された（テストの対象外になった）場合は登録しません。問題を準備している間にスキルが無効化されたときは、受験を始めません。
- メンバーの結果画面には、**レベルごとの正解数・正答率・判定と結果のレベルだけ** を表示します（各問題の正解・解説は表示しません）。

### 受験のルールと不正の防止
- **正解はブラウザに送りません**（受験中も終了後も）。問題は1問ずつで、**前の問題には戻れません**。
- 制限時間は **サーバーで計ります**（問題を初めて表示した日時を保存。再読み込みしても残り時間は戻りません）。制限時間を5秒（通信の遅れの分）過ぎてから届いた回答は時間切れ（不正解）です。
- 途中で画面を閉じても、開き直すと続きから再開します。ただし **全体の期限**（各問の制限時間の合計＋10分）を過ぎた受験は、次に画面（一覧・出題・管理画面）を開いたときに自動で終了し、未回答を時間切れとして同じように採点・登録します（終了日時・登録日はその時ではなく全体の期限の日時になります）。
- 受験中のテストは1人1つ（受験中に別のスキルは始められません。開くと再開します）。同じスキルの **再受験は前回の受験開始から7日後** から（設定で変更可。0 なら制限なし）。
- ほかのタブ・ウィンドウへの切り替え（ブラウザの `visibilitychange` / `blur`）を **回数として記録** し、マネージャーが受験履歴と詳細（問題ごとの回数）で確認できます（ページの再読み込み・リンクでの画面移動は数えません）。
- 問題文の選択・コピー・右クリック・印刷を画面側で抑止します（軽い対策で、完全には防げません）。
- **防げないこと**: スマートフォンでの撮影、別の端末での検索、他人に代わりに受けてもらうことなど。離脱回数・問題ごとの所要時間は、結果を見るときの判断材料として使ってください。

### 問題プール（AIで作成）
- 問題は AI（`app.py` の「4-1」の `ai_chat()`。接続先はシステム設定の「基本設定」タブ＝`instance/config.py` の `AI_〜`）が作成し、DB に保存して繰り返し使います。AI には **スキル名・カテゴリ・説明（スキル項目の「説明」）・レベルの意味（到達尺度の文言）** を伝えます。AIへの指示は「特定の組織に依存しない一般的な知識・技能を問う」「正解はちょうど1つ」「もっともらしい誤りの選択肢」「『すべて正しい』『どれでもない』は使わない」「JSONの配列だけを返す」です。説明に見出しがあれば、「**対象範囲の中から出題し、範囲の外からは出題しない**」「**出題しない範囲は出題しない**」「道具・言語・ソフトは説明に書かれたものだけ」「難易度はレベルごとの目安に合わせる」も指示します（説明が無いときは、スキル名とカテゴリから一般に想定される範囲で出題します）。
- AI の応答は厳しく検証し、条件を満たす問題だけを保存します（選択肢がちょうど4つで互いに異なり空でない・正解の位置が0〜3・長さの上限・既存の問題と内容が重複しない）。1問だけを頼んだときに AI が配列ではなく問題1つのオブジェクトで答えた場合も、その1問として読みます。
- AI が未設定のときは問題を作れないため、問題の無いスキルの一覧には「AIが未設定のため、問題を作成できません」と表示します（基本設定タブへのリンク付き）。
- 受験の開始時に、その人が見たことのない問題が足りなければ、**その場で AI が不足分を作ります**（10問ずつ。1〜2分かかることがあり、画面に「問題を準備しています」と表示。待ち時間が長くなりすぎないよう、約2分半を過ぎたら新しい作成はしません）。AI が使えない・失敗した場合は、その人が以前に見た問題を **見たのが古い順に再出題** します（受験履歴の「再出題」に件数を記録）。それでも足りなければ「問題が準備できません。マネージャーに連絡してください」と表示し、受験を開始しません。
- マネージャーは「問題プール」で、スキル・レベルごとの問題数を確認し、**補充**（各レベルの有効な問題が目標数〔既定 20問〕になるまで AI で作成。バックグラウンドで実行し、結果は「前回の補充の結果」に表示）ができます。受験者を待たせないよう、事前の補充をおすすめします。
- AI の作った問題は誤りを含むことがあります。問題の一覧（正解・解説・出題回数・正解回数を表示）で確認し、不適切な問題は **無効** にしてください（今後は出題しません。受験履歴には出題時点の問題文・選択肢の控えが残ります）。

### スキルの説明（出題範囲）
問題の精度は、スキル項目の **説明**（スキルマップの「スキル項目の管理」→ 編集。DB の `skills.description`）で大きく変わります。次の4つの見出しで書くことをおすすめします。

| 見出し | 書くこと |
|------|------|
| ■対象範囲 | このスキルで扱う知識・作業の範囲（テストで問う範囲） |
| ■使う道具・言語・ソフト | 使う道具・プログラミング言語・ソフトウェア（分かればバージョンや機能の範囲も） |
| ■レベルごとの目安（Lv1〜Lv4） | 各レベルで具体的にできること（到達尺度の文言を、そのスキルの言葉で書く） |
| ■出題しない範囲 | テストで問わない内容（ほかのスキルで扱う内容・使わない機能など） |

- スキル項目の追加・編集の画面の「**AIで下書き**」は、スキル名・区分・カテゴリ・到達尺度（Lv1〜Lv4。今の説明があればそれも参考）から、この4つの見出しで下書きを作って説明の欄に入れます。**保存はしません**（内容を確認・修正してから「更新」「追加」で保存）。AI が未設定・失敗した場合はその旨を表示し、説明の欄は変えません。JavaScript が無効なときは、入力を残したまま下書きを入れた画面を表示します。
- 問題プールの画面では、説明の無いスキルに「**説明なし（問題の精度が下がります）**」と表示し、編集画面へのリンクを付けます（スキルごとの問題の一覧では、説明の内容と、足りない見出しも表示します）。
- 説明を変えたときは、スキルごとの問題の一覧の「**このスキルの問題をすべて停止**」（確認あり）で、古い説明で作った有効な問題をまとめて無効にしてから「AIで補充」で作り直します（無効にした問題は受験履歴に残り、1問ずつ有効に戻せます）。そのスキルの補充の実行中は停止できません（補充が後から問題を保存し、古い説明の問題が有効のまま残るため）。補充が終わってから実行してください。

### 管理画面（マネージャー）
| 画面 | 内容 |
|------|------|
| 受験履歴 | 全員の受験（メンバー・スキル・状態で絞り込み、見出しで並び替え）。正解数・正答率・結果・到達度の登録（前→後）・離脱回数・再出題数。詳細では全問の問題文・選択肢（表示した順）・正解・本人の回答・所要時間・時間切れ・問題ごとの離脱回数・解説 |
| 問題プール | スキル・レベルごとの有効/無効の問題数（合計の列も表のレベルの有効な問題の数で、無効にした問題は括弧の中）、説明の無いスキルの警告（受験の対象のスキルだけ）、AI での補充、問題の一覧と無効化/有効に戻す（押したボタンの状態にする。古い画面で押しても逆にならない）、スキルの問題をすべて停止 |

設定（下の表）はシステム設定の「スキルテスト」タブで変更します（スキルテスト管理の画面の「設定はシステム設定で変更」から移動できます）。

### 4択テストで測れないこと（限界）
- 確かめられるのは、そのスキルの **知識と判断の一部** です。実際に作れるか（作業の速さ・品質・手順）、指導できるか・勉強会を開けるか（**Lv5・Lv6**）、**コンセプチュアルスキル・ヒューマンスキル** は測れないため、これまでどおりマネージャーが評価します。
- 4択はまぐれでも25%当たり、1レベルあたりの問題数も少ないため、結果には誤差があります。AI の問題の質・難易度にもばらつきがあります。自動登録は到達度を上げる方向にしか変えないので、実態と合わない場合はマネージャーが到達度を修正してください。

## AI分析（サマリーと推奨アクション）

マネージャーダッシュボードの「**AI分析（サマリーと推奨アクション）**」ボタン（`/manager/analysis`）から開きます。マネージャーのみ（メンバーは画面・データのどれも見られず、URL を直接開いても 403）。
チームの状況を4つの観点にまとめ、**いまマネージャーが対応すること（推奨アクション）** を優先度の高い順に示します。
数値と一覧はすべてアプリ（`app.py` の「9」）が計算します。画面を開くとすぐに表示されます。DB のテーブルは追加・変更しません（読み取りのみ）。
「**AIで分析**」を押すと、AI がタスク・コメントなどの本文を読んで判定・書き直し案・所見・推奨アクションを加えます（「[AIで分析](#aiで分析)」）。AI が未設定・失敗のときも、アプリの集計とルールによる推奨アクションはそのまま表示します。

### 期間
- **期間内**: 画面で「直近7日 / 14日 / 30日 / 90日」または「日付で指定」（開始日〜終了日）を選びます。既定は直近30日（両端の日を含む。今日より後の日は今日まで。2000/01/01 より前の日付は指定の誤りとして注意を表示し、直近30日で表示）。
- **現時点**: 期限超過・期限が近いのに未着手・記載がない・保留・負荷・スキルの分布と偏りは、今の状態です（過去の期間を選んでも、期間の後に登録されたタスクを含む今のタスクすべてが対象）。
- 未完了のタスクは、期間に関係なくすべてのコメント・状態の変更を対象にします。
- 営業日は土日・祝日を除いて数えます（期限超過通知と同じ祝日の計算）。件数が少ない中央値・割合には「**対象○件のため参考値**」と付けます（5件未満）。

### しきい値（システム設定の「AI分析」タブ）
| 項目 | 既定 | 内容 |
|------|------|------|
| 期限が近いとみなす営業日数（N1） | 5 | 「未着手」で、期限まで残りこの営業日数以内のタスクを「期限が近いのに未着手」にする（今日が期限なら残り0） |
| 記載がないとみなす営業日数（N2） | 10 | 「進行中」で、担当者の最後の進捗記載（記載が無いとき・進行中にした後に記載が無いときは進行中にした日）からこの営業日数以上たったタスクを「進行中なのに記載がない」にする（進行中にする前の記載は起点にしない）。保留がこの日数以上続くタスクも推奨アクションの候補にする |
| 1回に送る材料の最大文字数 | 12000 | 「AIで分析」で AI に1回で送る材料（タスクの本文など）の上限（2000〜100000）。1人分がこれより長いときは、タスクのまとまりごとに複数回に分けて送ります（省略はしません）。チームのまとめの材料が長いときは、詳細な一覧を先に分けて要約してから送ります。接続先の AI が一度に受け取れる量が少ないときは小さくします |

保存先は `instance/ai_analysis_settings.json`（Git 管理外。保存したときに作成。無い・読み込めない場合は既定値。読み込めないファイルは上書きしません）。

### ① タスクの進捗
- **進み**（期間内）: 完了したタスク（最後に「完了」にした日時。状態の変更の記録が無い完了タスクは更新日時で代用し「推定」）、着手したタスク（期間内に「進行中」になった）。
- **遅れ**（現時点）: 期限超過（超過した営業日数。今日が土日祝で 0営業日のときは「0営業日（N日超過・休日）」）、期限が近いのに未着手（残りの営業日数）、進行中なのに記載がない（経過した営業日数と起点）。
- **課題**: 保留中のタスク（保留にした日からの営業日数・最後の記載）。
- **マネージャーのコメントへの対応**: 未完了のタスクへのマネージャーのコメント（全期間）と、期間内に書かれたコメントが対象です（そのタスクの担当者でもあるマネージャーの記載は除く）。後に担当者のコメントが無いものを「**返信なし**」とし、書かれてからの営業日数を表示します（担当者のいないタスクは、マネージャー以外のだれかのコメントがあれば返信あり）。「了解です」「ありがとう」のような、了解・お礼・あいさつだけのコメントは「対応不要」として数から除きます。
- 「AIで分析」の後は、返信のあるコメントについて AI がマネージャーの求めたこと（指示・質問・依頼）を読み取り、後のコメントと状態の変更から「**対応済み／一部対応／未対応**」を判定し、残っている対応と根拠（使ったコメントなど）を表示します。返信のないコメントは「返信なし」のまま（判定はアプリ）です。求めていることの無いコメント（励ましなど）は「対応不要（AI判定）」として数から除き、一覧で確認できます。
- チームの件数とヒト別の件数（複数担当のタスクは各担当に数え、チームは1件として数える）、要フォローの一覧（「返信なし」「未対応」「一部対応」。タスクへのリンク・担当・コメントと日付・判定・残っている対応・経過）。
- 「AIで分析」の後は、未完了のタスクのコメントから AI が抜き出した **課題・相談**（根拠のコメント付き）も表示します（保留中のタスクには、その課題を並べて表示）。
- 判定はコメント・タスク・人の ID だけでなく、タスクの印（ID と登録日時）・コメントを書いた日時・ログインIDと一緒に保存します。分析の後にタスクやメンバーを削除し、同じ ID が別のコメント・別の人に再利用されても、前の判定・書き直し案・所見は出しません（所見は「分析の後に変更あり」）。
- 分析の後にコメント・状態・成果などが変わった項目は「**分析の後に変更あり**」と表示し、その AI の判定・書き直し案は使いません（返信のあるコメントは「未判定」として要フォロー・推奨アクションから外し、返信のないコメントは「返信なし」のまま。課題・相談は印を付けて残す）。もう一度「AIで分析」を実行すると判定し直します。

### ② スキル状況
- **スキルテスト**（期間内に始めた受験）: 受験・終了・時間切れ／途中で終了（受験中のまま期限を過ぎたもの）・受験中・レベルアップ・離脱が多い受験（画面から3回以上離れた）。**未受験**: 一度も受けていないメンバー、期間内に受けていないメンバー（以前は受験）。「最後の受験」と未受験の一覧は期間の終わりの時点で数えます（過去の期間を表示したとき、期間より後の受験は数えません）。受験を勧める推奨アクション（と AI に送る「一度も受験していない（現時点）」）は、今までに一度も受験していないメンバーだけです。
- **スキルの分布**（現時点）: メンバーごとの区分別の Lv2以上の数・平均到達度・得意なスキル（画面は上位5件。AI には保有しているスキル〔Lv1以上〕をすべて送ります）。
- **偏り**: Lv2以上の保有者が1名以下のスキル（必要な業務も表示）、必要スキルをすべて満たすメンバーが1名以下の業務、少数の人への集中（Lv2以上の保有の合計のうち1名が50%以上。対象者3名以上のとき）。

### ③ 成果物の状況（チーム全体とヒト別）
- 期間内に完了したタスクの成果（定量の見込み・実績・単位・補足、定性の見込み・実績）をルールで確認し、「**書き直し推奨**」の一覧（理由・今の記載・タスクへのリンク）と指摘の種類ごとの件数を表示します。
  「AIで分析」の後は、AI のあいまいさの判定（「あいまい（AI判定）」）を指摘に加え、書き直し推奨の行ごとに **書き直し案**（そのタスクとコメントに書かれた事実だけ。材料に無い数値は「◯」）と「**案をコピー**」ボタンを表示します。案は自動では反映しません（タスクを開いて貼り付けます）。
  ルール: 実績が空（見込みだけ）／ 数値に単位がない ／ 定量の実績に補足（根拠・計算方法）がない ／ 実績が見込みの50%未満・200%超（年換算）／ 定性の実績が15文字未満・補足が10文字未満。
- 成果の合計（金額 ￥/年・時間 ｈ/年。マネージャーダッシュボードの成果と同じ年換算。ヒト別は複数担当を担当者の数〔無効化した人を含む〕で均等割り。チームの合計にはマネージャー・無効化した人の分も含むため、ヒト別の合計とは一致しないことがあります）。
- **リードタイム**（着手→完了の暦日。着手は開始日、無ければ登録日）の中央値をヒト別・チームで表示し、規模の目安日数と比べます（目安を超えた件数）。

### ④ 各人の能力（総合）
指導の参考の表です（**順位・点数は付けません**。表示名順）。同時進行数（進行中／未完了）と負荷（マネージャーダッシュボードと同じ計算）は現時点、リードタイム・成果の件数と金額・時間・成果の書き方（書き直し推奨の件数）・進捗の記載の頻度（期間内の記載 ÷ 期間中に未完了だった担当タスク ÷ 週数）と具体性（定型の言葉だけ・短く数字の無い記載を書き直し推奨として数える）・マネージャーのコメントへの返信率（期間内に書かれたコメントのうち本人が返信したもの。複数担当のタスクで共同担当だけが返信したものは「共同担当が返信」として別に表示）は期間内です。
「AIで分析」の後は、AI が具体性が低いと判定した進捗の記載も書き直し推奨に加え、書き直し案と「案をコピー」を表示します。また、ヒトごとの **所見**（強み／気になる点／支援のポイント）を表示します（分析の後に追加・復帰した〔またはメンバーにした〕人は「分析の後に追加」と表示し、もう一度「AIで分析」を実行すると作成します）。

### 推奨アクション
期限超過・マネージャーのコメントに返信なし・進行中なのに記載がない・期限が近いのに未着手・長い保留・負荷が高い（160h/月以上）・対応できる人が1名以下の業務・保有者が1名以下のスキル・成果や進捗の書き直し推奨・スキルテスト（未受験・時間切れ・離脱が多い）から、優先度の高い順に最大10件を選びます（種類ごとの点数の帯の中で並べ、期限が近いのに未着手は、しきい値 N1 を大きくしても進行中なのに記載がない・返信なし・期限超過より上にはしません。同じ種類は数件まで。候補が5件に満たないときは同じ種類からも補います。1つのタスクに返信の無いマネージャーのコメントが複数あっても、そのタスクのアクションは1件にまとめます）。
担当者が全員無効化されたタスクは、担当者のいないタスクと同じく「担当者を決めて…」とし（無効化した人には頼みません）、一覧・AI に送る材料では名前に「［無効］」を付けます（AI には「担当者のいないタスク〔マネージャーだけ・無効化したメンバーだけが担当のものを含む〕」として送ります）。
各アクションには、やること・対象（タスク／ヒト／スキル／業務へのリンク）・理由・根拠の数値を付けます。
「AIで分析」の後は、AI が材料とこの候補をもとに選んだ推奨アクション（5〜10件）を表示します（ルールで選んだものは折りたたんで表示）。AI の推奨アクションの対象は候補か実在するタスク・ヒト・スキル・業務だけで、根拠の数値は材料にある数値だけです（5件に満たないときはルールの候補で補います）。AI が未設定・失敗のときは、ルールで選んだものを表示します。

### AIで分析
画面上部の「**AIで分析**」を押すと、表示している期間で AI による分析を別のスレッドで始めます（画面はすぐに戻り、実行中は進み具合を表示。終わると画面が自動で更新されます。同時に1つだけ）。AI の接続先は、週報などと同じくシステム設定の「基本設定」タブの `AI_API_URL` / `AI_API_KEY` / `AI_MODEL` です（未設定ならボタンは使えません）。

- **送る内容**: タスクの名前・説明・すべてのコメント（書いた人の氏名・日時）・状態の変更・成果（完了したタスクの記載と、未完了のタスクの途中の記載・見込み。長い欄も省略しない）、メンバーの氏名、スキルの分布と偏り（保有しているスキルはすべて）、スキルテストの受験の内容。画面にもこの注意を表示します。件数などの数値はアプリが計算して「【数値】」として渡し、AI には計算・創作させません（応答に材料に無い数値があれば「◯」に置き換え、画面に出す文で置き換えた数を表示します。件数・時間などの数量は材料の本文・数値にあるものだけを認め、登録・期限・コメントの日時や T12 のような ID の数字は数量として認めません。日付・時刻は材料にあるものだけ〔「10月」「2026/10」のような月・年月は、材料の日付にある月・年月なら認めます。「3/5」のような分数は、材料の日付に無くても数値がすべて材料にあれば認めます〕）。タスク・コメントの本文はデータとして渡し、本文の中の指示には従わないよう AI に伝えます（本文の中の「■」「【】」などの見出しの記号は別の記号に置き換えて送ります。チームのまとめの材料に入れる AI の文〔所見・分かったこと・スキルのまとめ・要約の要点〕も、同じく記号を置き換えて1行にします）。
- **送る順**: ①メンバーごと（その人に関係するタスク〔未完了のもの・期間内に完了や動きがあったもの〕の全文とその人の数値）→ 担当者のいないタスク → ②スキル → ③チームのまとめ（観点ごとのまとめと推奨アクション）。1人分が「1回に送る材料の最大文字数」より長いときは、タスクのまとまりごとに分けて送り、最後にその人の所見だけを作る呼び出しを1回加えます（長いタスク・コメント・成果の欄も途中で分けて送り、省略しません）。1件のタスクを分けて送るときは、状態の変更を毎回の見出しに付け、マネージャーのコメントへの対応と成果の判定はそのタスクの最後の回で頼みます（それより前の回で AI がまとめた経過メモ・成果の事実メモと、前の回で送ったマネージャーのコメントの本文を最後の回に渡します〔1回に送る文字数に入りきるときは全文、入りきらないときは先頭の約200文字、それも入らないときは本文を省いて AI の経過メモだけ（メモも短くすることがあります）〕。前の回が失敗したタスクの判定は頼まず「未読込」）。チームのまとめの材料が「1回に送る材料の最大文字数」より長いときは、要フォローのコメント・課題・保留・各人の数値と所見の一覧を先に分けて要約し、件数・要約・推奨アクションの候補（入りきる数まで。残りは件数）を送ります。
- **応答の確認**: 応答は JSON として読み、判定を頼んだ項目の ID・選択肢・長さを確かめます。JSON として読めないときは1回だけ頼み直します。
- **読めなかったもの**: 呼び出しが失敗した材料は「**未読込: ○件**」（タスクの件数と、スキル・チームのまとめなどの回数）として内訳と理由を表示し、残りはそのまま続けます（項目ごとにも「未読込」と表示。読んだ・読めなかったコメントの数は、複数担当のタスクで2回送っても1件として数えます）。3回続けて失敗したときは残りを中止します。1回の呼び出しが `AI_TIMEOUT`（秒）を超えると失敗になるため、メンバー・タスクが多いときは `AI_TIMEOUT` を長くするか、「1回に送る材料の最大文字数」を小さくします。1回も成功しなかったときは保存せず、前の結果を残して失敗の理由を表示します。チームのまとめが失敗したときは、ルールの推奨アクションを表示します。
- **保存**: 結果は `instance/ai_analysis.json` に最新の1回分だけを上書きで保存します（作成した日時・期間・モデル名・呼び出しの成否、判定ごとに使った材料の指紋〔分析の後の変更を見つけるため〕を含む。APIキー・接続先の URL は保存しません。DB には保存しません）。画面は、表示している期間と結果の期間（開始日・終了日）が同じときに結果を反映し、違うときは「その期間で表示」のリンクを出します。メンバーは画面・実行・状態・結果のどれにもアクセスできません。

## データベース

- **SQLite3**（`instance/app.db`。`instance/` は Git 管理外）。起動時（`flask --app app run` / `seed` / `migrate`）に、足りないテーブルを `db.create_all()` で自動作成します。
- サンプルデータの投入は `flask --app app seed`（既存データがある場合は各テーブルごとにスキップ）。
- スキルテストのテーブル（`skill_test_questions` / `skill_test_attempts` / `skill_test_answers`）は新しいテーブルなので、既存の DB でも起動時に自動で追加されます（既存のテーブル・データは変更しません）。
- 以前の「報告書」機能のテーブル（`reports` / `report_tasks` / `report_templates` / `ai_settings`）は DB に残りますが、現在のコードからは使用しません（削除は不要です）。
- **既存テーブルへの列の追加** は `db.create_all()` では反映されません。コードを新しくしたあとは、データを残したまま `flask --app app migrate` を1回実行すると、不足している列を `ALTER TABLE ... ADD COLUMN` で追加します（既存のデータは削除・変更しません。何度実行しても安全）。
  - 足りないテーブルも `migrate` で作成し、「作成されたテーブル」として名前を表示します。
  - `--check` を付けると確認だけ行い、DB を変更しません（不足しているテーブル・列を表示するだけで、テーブルも作りません）。`--db パス` で `instance/app.db` 以外の既にある DB ファイル（バックアップのコピーなど）を対象にできます（そのとき `instance/app.db` には触れません。パスを間違えたとき・SQLite の DB ではないファイルを指定したときはエラーで止まり、新しい DB は作らず、ファイルも変更しません）。
  - SQLite の制約により、NOT NULL の列は自動では追加できません（「★手動対応が必要」と表示）。DB にだけ残っている使われない列は、そのまま残します（参考として表示）。
- まっさらに作り直す場合だけ、`instance/app.db` を削除してから `flask --app app seed` を実行します。

## 以前の版からの更新

`app/` フォルダと `serve.py` などのスクリプトに分かれていた版から更新する手順です（ファイルをコピーして配置している場合）。

1. サーバーを止めます（自動起動のタスクがあれば、そのタスクも止めます）。
2. 念のため `instance/` フォルダ（DB・設定ファイル）をコピーしておきます。
3. 新しいファイル（`app.py` / `templates.html` / `ldap_client.py` / `README.md` / `requirements.txt` / `.gitignore`）を配置します。
4. **古いファイルを削除します**: `app/` フォルダ全体、`serve.py`、`run.py`、`seed.py`、`migrate.py`、`config.example.py`。
   - `app/` フォルダが残っていると、`flask --app app` は `app.py` ではなく古い `app/` フォルダのコードを読み込みます（Python は同じ名前のフォルダを優先するため）。Git で更新した場合は、`app/` に `__pycache__` だけが残ることがあります（読み込まれませんが、削除してかまいません）。
   - `ldap_client.py` の場所は `app/auth/ldap_client.py` からプロジェクト直下に変わりました。サーバーで本番用に書き換えた `app/auth/ldap_client.py` を使っている場合は、`app/` を消す前に、そのファイルをプロジェクト直下の `ldap_client.py` として置いてください（中身の変更は不要です）。
5. `instance/`（`app.db`・`config.py`・`*.json`）はそのまま使います。DB のテーブル・列は変わっていないため、`migrate` は不要です（`flask --app app migrate --check` で確認できます）。
   - 以前の版で自動作成した `instance/config.py` の `ADMIN_PASSWORD` の説明（「空にすると admin でのログインは無効になります」）は誤りです。空にすると `admin` の確認は `ldap_client.py` に任され、同梱の `ldap_client.py` では既定の固定パスワードでログインできます（「[固定ローカル管理者](#固定ローカル管理者)」）。`ADMIN_PASSWORD` は空にしないでください。
6. 自動起動（タスク スケジューラなど）で `python serve.py` や `waitress-serve ... --call app:create_app` を実行していた場合は、`flask --app app run --host 0.0.0.0 --port 8050` に置き換えます（「[サーバーの起動時に自動で起動する](#サーバーの起動時に自動で起動する)」）。
   - 待ち受けのアドレス・ポートは `instance/config.py` の `SERVER_HOST` / `SERVER_PORT` ではなく、`--host` / `--port` で指定します。以前と同じ URL で使うには、以前の値（既定は `0.0.0.0` / `8050`）を指定してください。ポートを変える場合は `APP_BASE_URL` も合わせて変更します。
   - `waitress` は使わなくなりました（入れたままでもかまいません。不要なら `pip uninstall waitress`）。追加で必要になったパッケージはありません。
7. 以前の版の **`.env` が残っている場合は、別の場所へ移すか削除してください**。`flask` コマンドは、python-dotenv が入っていると、今いるフォルダ（またはその上のフォルダ）の `.env` を自動で読み込んで環境変数にします。アプリ（`app.py`）は環境変数を読みませんが、`FLASK_` で始まる値は `flask run` の動き（デバッグモード・ポートなど）を変え、`ldap_client.py` が環境変数を読む実装なら（同梱のダミー実装は `admin` のパスワードに `ADMIN_PASSWORD` を使用）その値も使われてしまいます。python-dotenv が入っていない場合は読み込まれず、起動時に `Tip: There are .env files present. ...` と表示されます。
8. `flask --app app run --host 0.0.0.0 --port 8050` で起動し、ログインできること、起動時に自動送信のスケジューラの起動が表示されることを確かめます。

### ファイルの分け方
- `app.py`: Python のコードすべて。先頭の説明に、起動のコマンド・ほかのコマンド・動作確認で差し替える関数・**目次** があります。章は「`# ####`」、節は「`# ====`」の見出しで始まります（例: 「3. モデル」「5-3. タスク」「11-1. スケジューラ」）。
- `templates.html`: 画面テンプレート・CSS・JavaScript を、ファイルごとのセクションにまとめたものです。`{#=== tasks/list.html ===#}` のように名前だけを書いた行から、次の区切りの行の前までがそのファイルの中身です。
  - 区切りの名前がテンプレート名です（`render_template`・`include`・`extends` で指定する名前）。
  - 名前が `static/` で始まるセクションは静的ファイルで、`/static/` の後ろに残りの名前を付けた URL で配信します（例: `static/css/style.css` → `url_for('static', filename='css/style.css')`）。

  - 静的ファイルは、`templates.html` を保存すると次の表示から新しい内容になります。画面テンプレートは `--debug` のときは次の表示から、それ以外はサーバーの再起動で反映されます。
- `ldap_client.py`: LDAP 認証。本番環境ごとに差し替えるファイルです（「[本番LDAPへの移行](#本番ldapへの移行)」）。

### 新しい機能の追加手順
1. `app.py` の「3. モデル」にモデルのクラスを追加します（新しいテーブルは起動時に自動作成。既存のテーブルへの列の追加は `flask --app app migrate`）。
2. 画面の Blueprint を作り（「5. 画面」の節が参考になります）、「12-2」の `BLUEPRINTS` に追加します。1つのファイルなので、関数名はファイル全体で重複しないようにします。ほかの画面と同じ名前のエンドポイントにしたいときは、関数名を変えて `endpoint=` で指定します（例: `@tasks_bp.route("/<int:task_id>", endpoint="detail")` の関数は `task_detail`）。
3. `templates.html` に `<機能名>/<画面名>.html` のセクションを追加し、`base.html` のセクションのナビにリンクを追加します。
4. `app.py` 先頭の目次と `templates.html` 先頭の目次に、追加した章・節・セクションを書き足します。

共通の部品（`app.py` の「2. 共通の部品」）:
- マネージャーだけの画面: Blueprint 全体なら `xxx_bp.before_request(managers_only)`、画面ごとなら `@manager_required`（「2-5」。未ログインはログイン画面へ、メンバーは 403）。
- 画面で編集する設定（`instance/*.json`）: 既定値で補う関数と保存できる項目を決めて `JsonSettings`（「2-3」）を1つ作ります（読み込み・保存・前回の結果の記録・ロック・壊れたファイルを上書きしない動きは共通）。
- 時間のかかる処理（メール送信・AI の呼び出しなど）: `start_in_thread()`（「2-6」）で、処理ごとのロックを使って別スレッドで実行します（同時に1つだけ）。
- 主キーで行を取り出すときは `get_or_404()`、フォームの数字は `form_int()`（「2-2」）。AI の応答の JSON は `parse_json_reply()`（「4-1」）で読みます。

### 環境ごとの設定（instance/config.py）の項目の追加
`app.py` の `Config`（「1-1」。既定値）と `CONFIG_TEMPLATE`（「1-2」。見本）に追加し、`FIELDS`（「10-1」）に項目の定義（グループ・表示名・説明・種類・再起動の要否・秘密かどうか）を追加します。定義を追加するまでは、システム設定の「基本設定」タブの「その他」に読み取り専用で表示されます。値は使うたびに `current_app.config` から読むようにすると、画面で保存したときにすぐ反映されます（起動時にしか読まない項目は `restart_required=True`）。環境変数（`os.environ`）や `.env` は使いません。

### ChatGPT-API（AI整形）の設定・移行
接続情報は `instance/config.py` の `AI_API_URL` / `AI_API_KEY` / `AI_MODEL` / `AI_TIMEOUT` に記入します（Git 管理外のため、キーがリポジトリに入ることはありません）。接続先がリダイレクトを返したときは、キーを別の接続先へ送らないよう、従わずにエラーにします（`AI_API_URL` には転送されない最終の URL を書きます）。システム設定の「基本設定」タブで変更すると保存と同時に反映され、「AI接続テスト」で確認できます（ファイルを直接編集した場合はサーバーの再起動が必要）。`AI_API_URL` と `AI_API_KEY` がどちらも空なら機能は自動的に無効になり、週報はルールベースの文章のみ、スキルテストは問題プールにある問題だけで出題します。
OpenAI互換のエンドポイント（自前のAPIなど）なら `AI_API_URL` をそのURLに変えるだけで移行できます。仕様が異なる場合は、**`app.py` の `_call_chat_api()`（「4-1」）の中身だけ** を書き換えてください（メッセージ列を受け取り、応答の本文を返す関数です。呼び出し側は `ai_chat()` の戻り値 `(本文, エラー)` にしか依存していないため、他のコードは変更不要）。

### 定期メールの追加
メール送信は `send_mail()`（「4-2」。テキスト版・HTML版・添付ファイル・宛先の指定に対応）、営業日の判定は `is_business_day()` など（「2-4」）を使います。
自動送信は「11-1」の `JOBS` にジョブ（設定の読み込み・実行時刻の判定・実行・失敗の記録）を追加します（スケジューラのスレッドは1本で、ジョブごとに実行済みの記録と例外処理を持ちます。動くのは `flask --app app run` のときだけ）。

### 動作確認で差し替える関数（app._now / app._call_chat_api）
次の2つは、呼び出すたびにモジュール `app`（`app.py`）から探すため、モジュールの属性を置き換えるだけで差し替えられます。
- `app._now()`: スキルテストの時刻と、AI分析の基準の日時（「現時点」・期間の終わり）はすべてここから取ります。差し替えると、制限時間・全体の期限・再受験の間隔や、AI分析の営業日数を、時刻を固定して確かめられます。
- `app._call_chat_api(messages)`: AI の呼び出し。差し替えると、AI に接続せずに週報の整形・問題の作成・AI分析を確かめられます（`AI_API_URL` / `AI_API_KEY` がどちらも空だと AI を使わない動きになり、この関数は呼ばれないため、どちらかに値を入れておきます）。

```python
from datetime import datetime

import app                                   # app.py（モジュール）

flask_app = app.create_app()                 # app.py と同じフォルダの instance/ を使う
flask_app.config["AI_API_KEY"] = "test"      # AI を「設定あり」にする（_call_chat_api が呼ばれるように）
app._now = lambda: datetime(2026, 10, 5, 9, 0)
app._call_chat_api = lambda messages: "（AIの応答の本文）"
```
`create_app()` は `app.py` と同じフォルダの `instance/`（本物の DB・設定）を使うため、動作確認はプロジェクトのコピーで行ってください。`import app` だけでは `instance/` は作られず、自動送信も動きません。

### 本番LDAPへの移行
プロジェクト直下の `ldap_client.py` の `authenticate()` 内「LDAP-API」ブロックのみを実 API 呼び出しに置き換えます。戻り値の形（`username / display_name / role / source`）は変更しないでください。固定ローカル管理者（`_LOCAL_ACCOUNTS`）とアプリ登録チェックはそのまま残します。
- アプリ側が `ldap_client.py` から使うのは `authenticate()` と `_LOCAL_ACCOUNTS`（`admin` の表示名・役割。`flask --app app seed` では `_DUMMY_USERS` も使用）だけです。本番用に作った `ldap_client.py` はそのまま置き換えて使えます（`_DUMMY_USERS` が無い場合、`seed` は `_LOCAL_ACCOUNTS` のユーザーだけを登録し、動作確認用のユーザーを使うサンプルデータは作りません）。
- `ldap_client.py` の `from app.models.user import ROLE_MANAGER, ROLE_MEMBER` は、`app.py` がこの名前でも読めるようにしているため、書き換えずにそのまま動きます。
- `ldap_client.py` は最初のログインのときに読み込まれ、その後は読み直しません。差し替えたらサーバーを再起動してください。
